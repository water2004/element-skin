# V2 错误协议

## 1. 适用范围与审计结论

本协议只覆盖普通 `/v2` JSON API。OAuth 2.0、OpenID Connect 和 Yggdrasil 继续使用各自协议规定的错误响应。

设计前对现有错误出口进行了审计：普通后端约有 370 处直接 `HTTPError`、164 种静态文本，service helper 另有约 141 处调用、83 种静态文本，并存在动态密码规则、字段索引、OIDC discovery 与上游服务错误。旧文本同时承担机器判断和用户展示，出现了大小写、语言、措辞不一致，也使前端只能比较文案。

审计后按实际失败语义归纳为三个互相独立的维度：受影响对象、失败操作、失败原因。字段名、限制值、索引等上下文不进入标识，而放入受控参数。

## 2. 响应结构

```json
{
  "error": {
    "object": "identity",
    "operation": "link",
    "reason": "conflict",
    "params": {}
  }
}
```

- `object`：受影响的资源、凭证或输入对象，例如 `identity`、`profile_name`、`access_token`。
- `operation`：失败的动作，例如 `link`、`validate`、`resolve`、`verify`。
- `reason`：跨对象复用的封闭原因枚举。
- `params`：可选的安全上下文；没有参数时省略。
- 普通 `/v2` 错误不返回 `detail`、`message`、`code` 或展示文本。
- HTTP 状态表达通用错误类别，三元组表达稳定的业务语义，两者必须同时正确。
- 未分类错误统一为 `server / handle / failed`，不得暴露 SQL、文件路径、密钥、上游响应正文或底层错误。

三个标识字段只允许小写字母、数字和下划线，且必须以字母开头。协议不使用点号拼接字段；文档和日志可以用 `identity.link.conflict` 作为三元组的简写。

## 3. 命名规则

### 3.1 object

`object` 使用名词，选择客户端需要识别的最具体对象：

- 字段本身具有独立语义时使用字段对象，如 `profile_name`、`redirect_uri`、`webhook_event`。
- 资源状态错误使用资源对象，如 `profile`、`identity_provider`、`oauth_grant`。
- 凭证错误使用凭证对象，如 `access_token`、`refresh_token`、`verification_code`。
- 不使用宽泛的 domain 名占位；删除 object 后不能仍完整表达错误语义。

### 3.2 operation

`operation` 使用动词，表达失败动作而不是模块名。常用动作包括：

`validate`、`decode`、`resolve`、`verify`、`create`、`update`、`delete`、`reserve`、`authorize`、`authenticate`、`link`、`bind`、`sync`、`subscribe`、`exchange`、`refresh`、`fetch`、`download`、`configure`、`consume`。

### 3.3 reason

`reason` 只能取以下值：

| reason | 含义 |
| --- | --- |
| `required` | 必需值、状态或能力缺失 |
| `invalid` | 格式、类型、枚举或凭证无效 |
| `not_found` | 对象不存在 |
| `already_exists` | 同一主体已具有该记录或关系 |
| `conflict` | 与其他记录或当前状态冲突 |
| `denied` | 已识别请求不被允许 |
| `expired` | 凭证或操作已过期 |
| `disabled` | 功能被配置为停用 |
| `unavailable` | 依赖服务当前不可用 |
| `failed` | 无法公开更多原因的执行失败 |
| `mismatch` | 已知值与绑定或预期不一致 |
| `unsupported` | 类型、格式或流程不受支持 |
| `incomplete` | 已提供对象缺少必要组成部分 |
| `too_large` | 字节或文件大小超限 |
| `too_long` | 字符串长度超限 |
| `out_of_range` | 数值不在允许范围 |
| `exhausted` | 可消费次数已耗尽 |
| `exceeded` | 项目数量或配额超限 |

reason 不得包含对象或动作，例如不用 `identity_already_linked`、`invalid_redirect_uri`、`link_failed`。

## 4. 关键业务映射

| 场景 | object | operation | reason | HTTP |
| --- | --- | --- | --- | ---: |
| 未认证 | `authentication` | `verify` | `required` | 401 |
| 权限不足 | `permission` | `check` | `denied` | 403 |
| 分页游标无效 | `pagination_cursor` | `decode` | `invalid` | 400 |
| 角色不存在 | `profile` | `resolve` | `not_found` | 404 |
| 角色名冲突 | `profile_name` | `reserve` | `conflict` | 400 |
| 同一账户已绑定该外部身份 | `identity` | `link` | `already_exists` | 409 |
| 该外部身份属于其他账户 | `identity` | `link` | `conflict` | 409 |
| 外部身份需要重新授权 | `identity` | `authorize` | `required` | 409 |
| 授权账户与绑定不一致 | `identity` | `authorize` | `mismatch` | 409 |
| 同一账户已绑定正版角色 | `official_profile` | `bind` | `already_exists` | 409 |
| 正版角色属于其他账户 | `official_profile` | `bind` | `conflict` | 409 |
| Webhook 事件超出应用权限 | `webhook_event` | `subscribe` | `denied` | 400 |
| 未分类内部错误 | `server` | `handle` | `failed` | 500 |

`already_exists` 与 `conflict` 的区别是客户端恢复行为：前者表示当前主体已经拥有目标关系，后者表示关系被其他主体占用或与另一状态冲突。

## 5. params

`params` 只允许协议定义的安全值，例如：

```json
{
  "error": {
    "object": "password",
    "operation": "validate",
    "reason": "invalid",
    "params": {
      "rules": ["min_length", "uppercase", "number"]
    }
  }
}
```

可使用字段名、索引、最大值和规则标识；不得放入自然语言、底层 `error.Error()`、SQL、完整上游载荷、token 或密钥。客户端不得依赖未写入协议文档的参数。

## 6. 批量操作

批量操作的单项失败直接携带同一错误对象：

```json
{
  "profile_id": "...",
  "profile_name": "...",
  "error": {
    "object": "profile_name",
    "operation": "reserve",
    "reason": "conflict"
  }
}
```

## 7. 协议例外

- OAuth 标准端点返回 `{"error":"invalid_grant"}` 等 RFC 错误。本项目不使用 `error_description` 承载后端展示文本。
- Yggdrasil 继续返回协议要求的 `error` 与 `errorMessage`。
- Webhook 投递记录的 `detail` 是内部投递诊断字段，不属于 HTTP 错误协议。

## 8. 客户端规则

- 前端根据完整三元组选择本地化文案和恢复动作，不比较展示文本。
- 未知三元组显示统一兜底文案，不尝试展示后端原始错误。
- Python SDK 的 `APIError` 暴露 `status_code`、`object`、`operation`、`reason`、`params` 与 `response_body`。
- OAuth 错误由独立的 `OAuthError` 表达，不伪装成普通 API 三元组。
- OIDC 浏览器回调无法携带 JSON 响应时，重定向使用 `error_object`、`error_operation`、`error_reason` 三个独立查询参数；不得再压缩成页面专用错误码。
