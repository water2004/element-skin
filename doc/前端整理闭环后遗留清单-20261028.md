## 3 原计划下一批：3.6.8 流程推广

### 3.1 上传材质优先

上传继续使用弹窗。用户已撤销将其做成独立页面的方向；库侧预览升级也不构成新增上传路由的理由。

**默认公开是已确认、尚未实施的功能要求。** 当前共享 `uploadForm.ts` 工厂仍为 `is_public: false`。后续应同时修改默认、重置和相应回归，而不只是让开关初次显示为开启：

- 首次打开、取消后重开、上传成功重置后重开，共用默认公开的新草稿。
- 用户可关闭公开；替换文件及失败重试保留当前选择，按实际选择提交。
- 未改动的新草稿不算未保存；关闭公开算修改，改回默认且无其他变化时恢复干净。
- 不追溯修改已上传材质的公开状态，不改变同 Hash 记录的后端归属规则。

完整交互还需逐项定义并验证：

| 环节 | 需要明确的结果 |
| --- | --- |
| 选择与替换文件 | 文件类型、皮肤／披风尺寸与模型校验，错误后保留哪些输入，替换文件会重置哪些推断。 |
| 预览与信息 | 加载、校验失败、渲染失败分别表达；备注、公开与提交入口可达；预览资源关闭后释放，再次打开正常。 |
| 草稿与退出 | 继续采用明确提交的表单语义；显式取消／X、遮罩／Esc、子层退出分别处理当前范围，不丢失已保存结果。 |
| 写入 | 防止重复提交；写入中禁止关闭、切换和冲突操作；失败保留本轮选择与输入，成功按确定规则清理。 |
| 布局 | 单独确定预览、字段与按钮排布；窄／短屏和软键盘验证，不把未来播放器或姿态控件提前塞入本批。 |

已有 UiDialog 关闭样板和局部测试不等于上传全过程已通过。涉及请求时验证精确内容及调用次数；校验、资源和写入失败要验证状态保留与清理边界。未来新增预览控件时区分纯查看状态与待提交数据修改。

### 3.2 其余流程及交互保护

继续沿用[阶段 3 历史梳理](阶段3组件与交互梳理.md)第 14—15 节的入口扫描，逐项推广其余弹窗／导航抽屉、外部身份、账号、认证与 OAuth 流程，不重新做同范围的首轮盘点。

每项明确保存触发、草稿所有者、取消／X／Esc／遮罩、失焦、子层退出、写入中行为、失败保留、成功清理、敏感输入清理、权限变化和焦点返回。对象逐项生效与设置页明确保存继续保留各自语义，不强行统一为自动保存。没有确认文字草稿的普通确认框也不必套用表单挽留。

五类详情已确认并实施的名称显式保存、名称草稿阻止其他业务写入、写入中禁止关闭及切换、分层退出，不作为缺失能力重做。**其他操作的确认强度仍有待审建议**，例如模型变更影响范围、应用到已有不同绑定的角色时是否确认；现有确认不能因视觉通过就视为所有建议已批准。采用前先逐项确认，避免叠加不必要警告。

已知未成功、结果不明、写成功但后续读取失败应分开：超时不等于回滚，取消等待不等于撤回服务器写入，读取失败不应触发重复写入。清理旧实现只针对确认无调用、已被替代的路径，不借回归批做无边界重构。

### 4.2 先补更新链路，再处理入口

统一区分首次尚无结果、确认空结果、已有内容更新、读取失败和无权限。核对进入／返回、参数及筛选变化、操作后读取、去重、取消、响应顺序、过期判断、后台更新及缓存失效；不能让旧会话／旧对象结果覆盖当前内容，也不能每页再写一套定时器。

刷新入口沿用已记录方向，实施前结合实际更新链路复核，不批量删除所有同名按钮：

| 区域 | 已记录方向 |
| --- | --- |
| 站点、邮件、彩蛋配置 | 保留明确的重新加载配置；有草稿先确认，不能因回到前台覆盖输入。 |
| 通知、管理列表、第三方应用管理、个人开发者区 | 保留有明确资源范围的更新入口与独立反馈。 |
| 个人已授权应用区 | 补齐进入／返回／撤销成功／外部授权返回及失败重试，再移除常驻刷新。 |
| 仪表盘 Fallback 状态 | 沿用自动更新及失败重试，再移除重复手动刷新；不将读取状态当作触发立即健康探测。 |
| 公共库、个人角色、衣柜 | 维持无常驻刷新入口，保证进入、参数变化及操作后的更新。 |

“读取服务器数据”“重新加载并放弃配置草稿”“恢复本地值”和浏览器整页刷新不是同一动作。浏览器离开使用适用的原生提示，不新增只调用整页刷新的站内按钮；也不能承诺用户强制离开时绝对阻止或保住未提交秘密值。

## 5 内容排布与移动端

### 5.1 设置页及其他页面重设计（R04）

用户已要求重新组织设置内容，可合并相关配置项的展示组。先逐页定义任务、依赖、组名、字段顺序、说明、折叠、行列密度与操作区，再安排独立实施；当前不是所有组名和布局已经定稿。

“安全与速率限制”与仅有单个字段的“令牌与认证”是合并展示候选，尚未确定最终组合。站点、邮件、彩蛋、Fallback 分别梳理，不机械套同一布局；表格还需明确列优先级、长值、行操作、筛选和分页，表单明确说明／错误／提交的关系。必要的表格容器内横向滚动不是天然缺陷。

**展示组与保存组分开定义。** 仅重排展示可以沿用原接口和保存范围；如果一个按钮要提交多个原组，必须同时定义未保存归属、分组成功基线、部分失败与秘密值清理。不得把前端顺序请求包装成后端事务，不为合组改变服务端配置结构。

已有字段级“未保存”提示、邮件后缀策略及彩蛋组级提示是已验收安排，不在新排布方案确认前随意替换，也不将字段标记自动推广全站。

### 5.2 建议的 3.7 移动端专项（R05）

已知反馈是角色／材质详情预览占据过多初始屏幕，信息和主要操作被推到下方。需要专门处理，但最终采用紧凑、折叠或其他预览布局，以及高度、断点和操作区形式，尚未确定。

建议范围包括五类卡片／详情和上传、顶栏／抽屉／页头／工具栏、表单与配置、表格及分页、首页与 footer；覆盖真实手机、窄桌面、短视口、横竖屏、软键盘及输入法、触摸操作、安全区、焦点返回和连续打开预览后的资源状态。

现有响应式规则或某个窄屏通过不等于该专项完成。公告预览当前的 50dvh 是已验收组件自身方案，不是全站预览高度规范。3.7 编号及整体实施范围仍是建议，不在本文自动启动。

### 6.2 skinview3d（R07）

维持[历史初步计划第 19 节](阶段3组件与交互梳理.md#19-skinview3d-初步计划后续独立工作)：确认 fork／发布归属 → 升级 Three.js 并验证原能力 → 独立披风／鞘翅预览 → 测试发布 → 单列站点接入。目标是无需构造完整人物再隐藏来展示披风；具体来源和版本到实施时重新核对，不把旧记录当作最新版本结论。

播放／暂停、姿态预设、2D 原图、2D／3D 切换为待评估能力，尚未确定控件方案。真实 WebGL、纹理与模型加载、资源释放、缓存、失败和设备性能需专项验证；测试环境模拟不代替渲染验收。本前端整理不顺带 fork、升级依赖或承诺未实测的性能收益。

后续下载产物优先使用材质名，缺省使用完整 Hash，保留正确文件扩展名。实施前细化缺省名称、合法文件名清理、冲突、文件来源、权限和失败反馈。当前“预留”仅指记录，不增加按钮、禁用占位或下载逻辑；如现有契约不足，先另立所需工作。

## 9 样式规范余项与已经明确的边界

### 9.1 硬编码与设计交付（R12）

继续以固定 `a2485e5` 清单逐项核销，不覆盖原 CSV／JSON／扫描证据，也不把 3.1／3.2 盘点完成写成全站硬编码清零。区分协议／材质尺寸、必要业务常量、具名页面例外和可合并的重复样式；不要为减少数字而将不同语义强行并为一个变量。

页头／页宽来源已经梳理并验收，但认证卡、授权面板、资料内卡、首页内容等仍有具名例外，需要在最终设计交付中明确采用范围。后续完成整轮整理时，核对设计约定与最终代码，收敛重复规则、移除已废弃提案，形成可供后续页面直接参考的稳定设计文档。

### 9.2 仪表盘卡片阴影（R13）

统计卡与启动器卡当前显式使用 `UiCard shadow="hover"`：常态无阴影，鼠标进入整卡（含留白）显示共享悬浮阴影，移出淡去；未启用卡片位移，也没有整卡点击跳转。该条只是已解释的源码行为，不将询问触发方式记作进一步设计确认。

后续复核阴影是否会暗示整卡可点击，以及触摸和键盘的表现；目前 CSS hover 没有专门限制设备能力，容器也不是普通 Tab 焦点。不要在未确认方案前给静态卡片新增 tabindex、点击动作或统一上浮。

### 9.3 不再作为未解决问题重复登记

- 页头渐变及字号／字重、首页媒体“未保存”的位置／原生入场、邮箱同行、公告初始高度及长预览独立滚动，本轮已由用户验收。
- 角色按钮双向过冲、可见提示框清理、按钮独立上移取消、卡片整体上浮／阴影和 A／B 语义色泛光，已完成本轮验收；C／D／E 未纳入推广，不等于遗漏。
- 自定义头像异步补入是已接受边界，错误字母头像闪现不是保留设计；资料头像原有悬浮动画已确认保留。
- 首页玻璃按钮着色层存在，背景会压弱感知；未批准另调颜色强度，不恢复已取消的边框。
- 邮箱框保留原 disabled 行为。用户已撤回扩展选中／复制功能的要求，不另立邮箱复制开发项。
- 上传仍为弹窗；下载、管理邮箱等“预留”不产生可见空入口。五类详情未绑定 Hash／清除入口的隐藏和现有模型／精度／正版标签，不因新清单重做。
