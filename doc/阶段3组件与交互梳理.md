## 1. 背景、目标与边界

阶段 2 已闭环，保留首页入场偶发不同步、自定义头像异步补入、全站弹层交互未统一三项边界。阶段 3 负责设计变量、组件语义、关闭与表单生命周期、动画；阶段 4 负责远程数据的加载、空结果、错误、刷新、重试与竞态。

本阶段目标：同类操作采用一致的视觉和行为，业务差异有明确归属；复用现有组件，移除被替代实现，而不是为每个 Element Plus 控件增加包装。

非目标：替换组件库、重做页面信息架构、修改 API 或数据库、调整权限模型、引入持久化草稿、实现清除头像入口、恢复 Webhook stash。自定义头像沿用用户已接受的异步补入策略。公共组件变更对现有调用方的影响仍需检查，但 Webhook 编辑器不纳入迁移范围。

3.1 只确认源码现状、规则建议、例外和迁移顺序；不将后续规则描述成当前产品已经具备的能力。

## 3. 设计变量与样式职责

### 3.1 盘点时的来源（3.2 实施后职责见第 11 节）

| 来源                                                                             | 已有职责                                                               | 待处理点                                                   |

| [base.css](../element-skin/src/assets/base.css)                                  | 语义背景、文字、边框、卡片、顶栏、预览背景；部分 Element Plus 变量映射 | 补齐状态、尺寸等缺口；核对旧调色板与实际用途，避免重复变量 |

| [element-overrides.css](../element-skin/src/assets/styles/element-overrides.css) | 全局 Element Plus 覆盖、输入过渡、按钮过渡、滚动锁定补偿               | 全局规则仅承载全站共识；保留阶段 2 滚动锁定修复            |

| UI／业务组件样式                                                                 | 局部圆角、阴影、渐变、间距和控件内部覆盖                               | 共性进入组件或变量；业务特有尺寸留在所属组件               |

### 3.2 3.2 要落实的变量分类

| 分类       | 使用语义                                                                   | 收敛方式                                                                      |
| ---------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 颜色       | 页面／容器／浮层、正文／次要／禁用、边框、主要操作、成功／警告／危险、焦点 | 继续采用既有 `--color-*` 体系，建立与 `--el-*` 的明确映射；同一颜色不双向引用 |
| 间距       | 页面边距、卡片内容、表单行、操作区间隔                                     | Tailwind 标准刻度优先；仅重复的组件契约使用专有变量                           |
| 圆角与阴影 | 控件、卡片、弹层、预览区                                                   | 按组件角色归类，减少业务页面逐项覆盖，不把所有容器强制设为同一圆角            |
| 尺寸与文字 | 紧凑／默认／大控件、图标按钮、标题与辅助文字                               | 对齐现有使用场景，明确实际点击区域和内容尺寸                                  |
| 状态       | hover、active、focus-visible、disabled、loading、selected、error           | 同一状态跨深浅主题保持可辨识；禁用／加载状态不触发悬停位移                    |
| 动画       | 控件反馈、弹层开合、页面入场、首页入场                                     | 时长／缓动／位移分开定义；具体数值在样板阶段通过用户视觉验收确定              |

源码已确认的例子：UiButton 写死多组渐变和阴影，UiSegmented 有暗色硬编码，PageHeader 写死图标底色，UiCard 声明 `shadow` 属性但自己的 CSS 仍设置阴影。后续需让组件公开语义与实际渲染一致。权限标签的分类色属于业务信息编码，应集中维护色系，不能压成统一主色。

### 4.2 拟定组件交互契约

以下为职责约定，具体属性名在 3.3／3.4 实现时确定，当前不新增一套并存组件。

| 交互概念                          | 提供方                      | 执行方                                               |
| --------------------------------- | --------------------------- | ---------------------------------------------------- |
| 操作意图、重要程度、图标、大小    | 业务页面／子组件 props      | UiButton 渲染状态与反馈                              |
| 是否已修改、初始表单、当前记录 ID | 持有表单的页面／流程        | 既有 dirty 抽象和业务重置方法                        |
| 是否正在提交／执行关键操作        | 业务流程                    | 弹层统一保护关闭、按钮统一 loading／disabled         |
| 请求关闭及来源                    | 遮罩、Esc、右上角、取消按钮 | 共同进入一个关闭判断，不让 footer 直接绕过           |
| 成功提交后结束、步骤切换          | 业务流程                    | 明确区别于用户放弃；不重复弹未保存确认               |
| 实际关闭后清理                    | 业务数据／资源持有者        | 清表单、校验、密码、预览 URL、计时器；组件仅通知时机 |

Ui 组件不调用业务 API，不读取会话或浏览器存储；页面与流程保留权限判断和业务编排。没有新增后端 API、数据库模型或存储格式。

### 14.1 口径与最终约定

2026-10-25，用户在指出上传纹理关闭提示遗漏后，确定按以下逻辑扫描，并明确该过程覆盖首轮验收反馈的扫描目标。本轮核对产品源码的 Vue 组件、所属页面、事件处理及保存 helper；83 个 Vue 文件中包含 20 个业务弹窗入口及 1 个导航抽屉。Webhook 编辑器保持冻结、排除业务检查。已提交行为基线为 `fc652b3`；上一轮中断前开始的上传等 13 个文件补正仍是未提交、未验证的工作区内容，不算已完成迁移。本次只补充扫描与分类记录，不继续改动产品保存行为。

分类单位是实际交互单元，不要求一个页面或一个 Vue 文件只有一种语义。用户进一步明确：站点设置属于对象编辑，但明确提交是刻意设计。因此“编辑什么”与“如何提交”必须分开记录，不能把对象编辑等同于即时保存，也不能把表单式交互理解为只用于创建：

1. **先判断是否有编辑行为**。展示、导航、搜索、筛选不创建待保存的业务草稿，关闭通常只结束查看；附带命令单独判断。
2. **业务性质**：区分编辑已有对象、创建对象／执行命令、只读／导航。站点设置、角色详情和编辑已有公告都在编辑已有对象，但不因此采用同一种提交方式。
3. **提交方式**：角色详情、材质详情按现有交互逐项即时提交，沿用 change／blur／Enter／选择触发，成功即生效；关闭不是放弃整表，不回滚成功修改。站点设置、编辑公告等采用表单式明确提交，提交前为草稿；独立表单取消／右上角直接放弃清理，遮罩／Esc 在有修改时确认。两种方式均需防重复、明确成功／失败并固定请求目标，不擅自将任何一种强加给所有对象编辑。
4. **确定草稿归属**。子组件改 props／emit 更新不等于已经写入服务器。父页面持有的草稿只能由父页面保存或放弃；关闭局部编辑器不能替父页面清空整份草稿。保存、关闭、放弃和重开按提交方式与草稿归属决定，不按对象是否已经存在决定。多步骤、文件、凭据、危险确认是附加规则。

### 14.4 其他浮层与危险确认

已复核 21 处 MessageBox confirm 和 2 处 prompt：共享“放弃修改”确认辅助表单退出；删除／清绑定／转让／撤销／同步等确认辅助单次命令；两个 prompt 是各自持有本轮输入的小表单。确认层的取消只取消该次命令，不可误报请求失败，也不可撤销此前已经完成的其他操作。确认是否必要由操作影响决定，不把对象编辑全部包上一层整表确认。

账户 popover、菜单、下拉选项和日期选择只是导航／输入附属浮层；图片放大是只读预览；它们关闭不等于关闭所属表单。尤其 Esc 应先关闭当前最上层，不能顺带放弃下层草稿。危险确认禁止遮罩误触、敏感字段清理、多步骤保留及关键提交中保护都是附加规则，不增加新的保存分类。

### 14.5 首页图片页的保留边界

本页归为父页面持有草稿的表单；HomepageMediaDialog 只是局部编辑器。名称、时长、遮罩、镜头、启用与顺序先改父页面 items，保存配置才依次 PATCH／reorder；上传和删除仍是独立即时资源命令。HomepageMediaCard 的启用开关虽然长得像其他页面的即时开关，这里仍只修改父页面草稿。

因此本次不将其改成即时对象编辑，不给局部编辑器套“取消就清父页面修改”的独立表单规则，也不擅自增加局部服务器保存或改变排序／上传／删除流程。后续单独核对整页保存、放弃、离开、重载、资源命令与部分成功之间的关系；只有在边界明确后才调整实现。本轮没有改动该页、局部弹窗或其保存 helper。

### 14.6 缺口与扫描结论

- **表单漏接**：已提交基线中，D08 上传纹理未接 dirty／busy，取消直接改可见状态；D11 创建邀请码、D17 封禁、D05 绑定正版存在同类关闭或提交保护遗漏；D06 远端导入已有清理和 loading 检查，但缺少间接退出的 dirty 判断。它们采用明确提交，需逐项补齐草稿退出规则；不把这些规则套到逐项即时生效的详情上，也不否定站点设置等对象编辑采用明确提交。
- **无编辑入口的请求保护**：D04 不需要 dirty，但授权开始后仅 footer 禁用不足以保护右上角／Esc 等入口；D20 的审核命令也应按单次操作保护，而不是给只读详情伪造草稿。D03 危险确认应清确认文字并保护执行，取消无需挽留这段文字。
- **对象编辑一致性**：D07／D18 的角色名、D09／D19 的材质备注／模型／公开状态应保留逐项生效。13.7 已列出的重复触发、目标切换、失败反馈和重试是实现缺口；即时保存本身不是缺陷，也不因此改为整表提交。
- **表单离开与局部归属**：整页表单尚未统一离页保护；dirty 标记不等于已经阻止丢失。公告两步、媒体局部编辑、Fallback 子编辑器及权限选择需按父页面／流程归属处理，不能在子组件自行清整份父草稿。

结论：**首轮反馈要求的全站扫描目标已由 13.7 与本节合并完成；剩余是按分类逐项实施和验证，不再单列一次同目标扫描。** 本轮没有新增产品代码改动、没有代替用户做视觉验收、没有提交或推送。上一轮中断前开始的 13 文件补正保持未提交、未验证状态；不能沿用 `fc652b3` 的 537 条测试结果为这些新增改动背书。扫描完成也不改变阶段 3.4 首轮验收未通过、修订待复验的状态。

## 15. 组件行为与交互契约

本节将第 14 节的分类落实为实施与验收规则，不再重复扫描。以下是目标契约，不能解读为所有组件已经具备这些行为；实际缺口仍按 14.6 记录。2026-10-25 本轮只更新文档，没有更改产品代码、执行真实业务操作或标记人工验收通过。

### 15.1 业务性质与提交方式分开确定

“对象编辑”回答编辑的是什么，“表单式明确提交”回答修改何时生效；两者可以同时成立。本站保留以下刻意的组合，不以统一语义为由改变保存方式：

| 入口 | 业务性质 | 提交方式与保留意图 |
| ---- | -------- | ------------------ |
| 角色、材质详情 | 编辑已有对象 | 逐项即时提交，保留字段完成编辑即生效的方式 |
| 站点设置 | 编辑已有设置对象 | 表单式明确提交，允许成组检查修改后再保存；必须保留现有保存按钮及组级草稿，不改为输入／失焦／开关变化即自动保存 |
| 编辑已有公告、身份提供方、OAuth 应用、个人资料 | 编辑已有对象 | 沿用表单式明确提交，不因存在对象 ID 而改为即时提交 |
| 新建角色、上传纹理、新建公告 | 创建对象／执行命令 | 表单式明确提交，提交前不创建或发布 |

下面按两种提交方式规定交互行为；右列同样适用于站点设置这类对象编辑。整页与局部边界见 15.4—15.5。

| 情形 | 逐项即时提交：角色／材质详情等 | 表单式明确提交：含站点设置等对象编辑 |
| ---- | ------------------ | ------------------ |
| 打开 | 显示该对象最近确认的值；加载不创建修改，也不自动写入 | 新建取默认值，编辑取目标记录建立本轮基线；默认选中、自动填充和首次随机预览不算用户修改 |
| 文本输入 | 先在当前字段中编辑，Enter 或失焦完成该字段后校验并提交；内容未变不请求，Enter 紧接失焦只请求一次 | 只改草稿；Enter 仅在业务明确支持提交时等同于提交按钮，不能绕过校验、提交锁或中文输入法组合输入 |
| 选项／开关 | 明确改变选项后提交该项；有危险影响时先做该项确认，取消恢复最近确认的状态 | 只改草稿；看起来相同的开关不能自行绕过父页面保存 |
| 成功 | 该次服务器操作立即生效，同步对应对象和列表；不等待关闭，不再增加整表保存 | 以实际提交的数据及返回值更新基线；独立创建／操作表单结束本轮并清理，整页编辑表单保留页面、清未保存标记 |
| 右上角／取消 | 只提供“关闭”，不提供暗示回滚的“取消修改”；不询问放弃整个对象，不撤销已成功修改 | 明确放弃本轮未提交输入，直接关闭并清理，不二次询问；已完成的独立操作不会被撤销 |
| 遮罩／Esc | 无待处理写入时结束编辑，不加整表 dirty 确认；先关闭最上层子浮层 | 草稿未变直接关闭；有实际修改则询问“放弃修改／继续编辑”。继续编辑保留字段、选择、文件和校验；放弃才清理。危险确认与父草稿局部编辑按后文处理 |
| 读取中 | 允许退出；迟到的读取结果不能重开弹窗或覆盖另一对象 | 普通策略／初始数据读取允许退出；未初始化完成不得提交，返回结果不能覆盖关闭重开后的新草稿 |
| 写请求中 | 显示该项正在保存，禁止重复及冲突操作；涉及该对象的关闭／切换入口暂不可用。关闭引发当前字段失焦时，先按该字段提交规则处理，不能先销毁详情、再把失败藏在后台 | 锁住本轮提交及影响载荷的字段，保护全部关闭来源；重复点击、Enter、取消、Esc 都不能并发提交或丢失请求结果 |
| 校验／写入失败 | 不把新值显示成已保存。文本保留失败输入及错误，允许明确重试或恢复最近确认值；开关／枚举恢复最近确认值，并保留错误提示。失败文字未处理时留在编辑位置，不静默当作成功关闭，也不把其他已成功字段整体回滚 | 保留本轮草稿、文件、步骤和可修正的校验信息，解除提交锁后可重试；不因失败重新加载覆盖输入，不显示成功，不自动从第一步开始 |
| 重新打开 | 取当前目标及已成功状态；上一对象的失败输入不能串入新对象，不恢复未保存的失败文字 | 上一轮已放弃或成功结束则重新初始化，清上轮校验；多步骤往返和父页面局部编辑不属于重新创建一轮 |

逐项提交详情的“关闭”不是保存按钮，但也不能绕过当前字段的完成编辑与错误处理。某项发生错误时，仅该项存在未确认状态，不因此给整个对象制造一份可回滚的整表草稿。采用明确提交的对象编辑则确实持有组级或整页草稿，关闭不能套用即时详情的规则。dirty 比较实际待提交内容与本轮基线；已选文件必须单独判断，不能依赖 File 的 JSON 序列化结果。

### 15.2 独立命令、确认层与无编辑入口

- **单次命令**：应用材质、添加到衣柜、清绑定、同步、授权／撤销、审核、删除等，仅在用户明确执行后请求。参数选择本身不执行。发起时固定目标与参数，执行中防重复和切换目标；成功只更新该目标，取消确认不请求也不报失败。
- **确认层**：文案明确操作、对象及影响，按钮用“清除皮肤”“删除角色”“确认封禁”等动作文字。危险确认遮罩不关闭，Esc／取消／右上角只取消本次命令，不挽留确认文字、不触发提交。确认之后的请求仍需执行保护；隐藏确认框不等于请求已经完成。
- **无编辑入口**：D04 提供方选择、D10 只读预览、D20 审核详情及 W01 导航，在没有写请求或上层子流程时直接关闭，不询问放弃。附带动作按上一条单独执行；不把列表查询、搜索词、筛选或菜单可见状态算作业务草稿。
- **嵌套顺序**：Esc／遮罩只影响当前最上层。关闭下拉、日期选择、图片预览或确认框不能同时关闭所属表单；子流程结束后焦点返回其入口，最终关闭回到页面触发入口。

### 15.3 各表单的生效、退出与重开

| 入口 | 明确执行的动作 | 退出／失败／重新打开规则 |
| ---- | -------------- | ---------------------- |
| D01 新建角色 | “创建”成功才生成角色 | 放弃清名称；失败留名称；下一轮名称为空；创建中保护全部关闭来源 |
| D02 重设邮箱 | “发送验证码”仅发码；“确认重设”成功才换邮箱 | 放弃清邮箱、验证码及校验，但保留本组件已开始的发码冷却；失败保留输入；关闭不能撤销已发送邮件，也不能用重开绕过冷却 |
| D03 注销确认 | 输入准确确认文字后“确认注销” | 适用危险确认规则；取消／Esc／右上角清文字，不增加放弃草稿确认，遮罩不执行关闭或注销；失败留在本轮确认，退出及卸载清文字 |
| D05 正版绑定 | “建立绑定”才创建关联 | 默认选中第一项为初始状态；主动改选计入草稿。放弃清选择，下一轮按当时可用身份初始化；失败保留本轮选择，不能自动换账户重试 |
| D06 远端导入 | “下一步”验证／预取角色，“确认导入”才写入本站 | 同一流程步间保留地址、凭据和选择；退出整个流程才清全部数据及凭据。预取失败留在输入步，导入失败保留选择；部分成功明确数量和结果，不能假称全部失败或让取消撤回已导入角色 |
| D08 上传纹理 | “确认上传”才上传文件与属性 | 文件、类型、模型、备注、公开选择都属于草稿；文件或选项任一有改动即可触发间接退出确认。放弃清 File／列表／属性及 Blob URL，失败保留它们供重试，成功后结束并释放预览；重开取默认值，无上次文件 |
| D11 创建邀请码 | “确认创建”才写入 | 首次生成预览不算修改，主动“换一个”算修改；放弃清模式、文本、次数和备注，本轮失败保留；重开生成新的默认预览，不沿用上轮手动码 |
| D12／D13 公告 | “下一步／返回编辑”仅切步，“创建公告／保存”才提交 | 同一流程共用一份草稿与基线，切步不确认放弃、不清理；取消／右上角退出整个流程，遮罩／Esc 按 dirty 确认。失败保留当前内容与设置，成功后结束流程；编辑已有公告也不逐字段发布 |
| D16 重置密码 | “确认重置”才改密码 | 两个字段均属本轮敏感草稿；失败保留供修正，放弃／卸载清两字段；重新打开为空，不写入持久化存储 |
| D17 封禁 | 选择时长并填写原因后“确认封禁” | 选择预设或填写原因不立即封禁；放弃清原因与时长，本轮失败保留；下一轮默认 24 小时并清原因，不能把上一用户输入带给下一用户 |

公告、远端导入等流程的步骤切换不是取消；密码、验证码、外部凭据、文件和预览 URL 也不是可跨关闭恢复的长期草稿。清理要由实际持有者执行，不能用 destroy-on-close 代替父页面状态清理。

### 15.4 对象编辑和整页表单的具体边界

| 入口 | 交互契约 |
| ---- | -------- |
| D07／D18 用户／管理角色详情 | 角色名在完成字段编辑后单独校验、请求并生效，保持即时保存；其他清绑定、设置头像、同步、删除是独立命令。名称已保存后关闭不问放弃；失焦与 Enter 不可重复请求，返回结果只能修改发起时的角色 |
| D09／D19 用户／管理材质详情 | 备注为文本字段提交；模型、公开状态为单项选择提交。各项成功互不依赖整表保存；单项失败不撤回其他已成功项。应用到角色先选目标再明确应用，关闭只清未执行的目标选择，不撤销已应用结果 |
| D15 用户详情／UserPermissionPane | 授予／撤销角色、设置／清除权限及账号命令各自生效；本地选择参数尚未执行时可以清理，不给整个用户创建统一草稿。封禁、重置密码是各自独立表单，取消它们不回退已修改的权限 |
| AdminNotices 列表开关 | 仅该公告 enabled 属性逐项生效；不得把开关成功解释成正在编辑的公告草稿已保存，失败恢复该项已确认状态 |
| 站点设置、邮件设置 | 属于已有配置对象编辑，刻意采用表单交互及显式提交。保留按组保存，只把对应组的提交结果更新为已保存基线；点击或改值本身不自动生效。别组草稿保留；重新加载和普通切页会丢草稿时应提示，显式取消／放弃只恢复对应组最近确认值，不删除设置对象，也不撤销已成功保存的其他组 |
| Fallback、彩蛋配置 | 父页面持有整页草稿，端点子组件和开关修改不立即生效；明确保存后才提交。重新加载、离开或放弃应针对整页处理，不让局部子组件清整页数据 |
| 身份提供方、OAuth 应用编辑 | 新建及修改既有对象都按显式提交表单处理；权限选择是应用草稿的一部分。轮换密钥、删除、重新提交审核等独立动作按各自结果表达，不暗示它们会连带保存所有当前输入 |
| 个人资料 | 显示名和密码属于显式提交表单；密码变更和资料 PATCH 的结果分别表达，部分成功不等于整份输入都未生效。个人本地彩蛋偏好是独立即时设置，不由资料保存按钮决定 |
| 身份标签、审核原因 prompt | 小型独立表单：确认且校验成功才执行；取消清本轮输入，失败保留可修正内容。prompt 不改变所属详情或列表的整体分类 |
| 登录、注册、找回密码、OAuth 授权 | 按明确登录／注册／重置／批准／拒绝动作执行；查询代码或展示权限不代表已批准。敏感输入、计时器及延迟动作按所属流程清理，不创建持久化凭据草稿；不把认证页面查询状态当成未保存的业务修改 |

整页表单中，明确“取消／放弃”与普通路由跳转分开：前者是主动丢弃对应草稿，后者在会丢失修改时询问是否离开；刷新／关闭页面采用适用的离开提示，不靠持久化密码或验证码恢复。保存期间不允许编辑造成“请求发的是旧值，基线却捕获新值”；重新加载不能静默覆盖未保存输入。多个请求的操作可能部分成功，必须保留未完成输入并区分已成功部分，不报告整页原子回滚。

### 15.5 首页图片：父页面草稿的局部编辑

此处明确边界但暂不改保存模型，不把它套成独立即时对象编辑，也不作为本轮批量实现项：

| 操作 | 明确含义 |
| ---- | -------- |
| 修改媒体名称、时长、遮罩、镜头 | 更新父页面中该媒体项的草稿，尚未写入服务器；媒体名称不是磁盘文件名 |
| 局部“完成”、右上角、Esc、遮罩 | 结束这次局部编辑并返回父页面，修改保留在父页面草稿；不是服务器保存，也不是放弃父页面修改。按钮应表达“完成／关闭”，不显示暗示局部回滚的“取消修改” |
| 卡片启用／停用、排序 | 修改同一父页面草稿，等待“保存配置”；不因为控件外观像即时开关就自行 PATCH |
| 父页面“保存配置” | 提交当前配置及顺序，成功后更新相应已保存状态；失败保留未完成输入，不重新加载覆盖草稿。PATCH 与 reorder 可能部分成功，不能承诺事务或一键撤回 |
| 父页面放弃／重新加载／离开 | 放弃的范围是未提交配置和顺序，不包括已上传或已删除的资源；普通离开／重载有修改时需确认。具体整页放弃入口与资源命令协调单独实施，不能由局部 X 代替 |
| 上传／删除资源 | 继续是独立服务器命令，不纳入局部关闭回滚。存在未保存配置时不自动先保存、不静默丢弃，先引导处理父页面草稿；执行后也不得让迟到的刷新覆盖新草稿 |

## 16. 新建角色名称提示补正

2026-10-25，用户在继续人工验收时发现新建角色输入框显示 32 字符上限，但后端只接受 1–16 位，并指出 Mojang 创建名称采用 3–16 位、英文字母／数字／下划线的规则。

- 当前实际接口：`internal/util/public_urls.go` 的 ValidProfileName 拒绝空值、超过 16 位及非 ASCII 英文字母／数字／下划线。新建、用户改名、管理员改名、远端导入及正版绑定复用此校验，当前最小长度是 1，不是 3。
- 本次 UI 修正：CreateRoleDialog 的 maxlength 从 32 改为 16，计数器随之修正；新增“1–16 个字符，仅限英文字母、数字和下划线。”说明。仅对齐当前真实接口，不在前端单方面伪装已经执行 3 位下限。
- 命名策略另列：用户指出的 Mojang 3–16 位要求是后端规则是否收紧的问题，不属于此次提示修正。若调整，需同时核对创建／改名、外部导入、正版绑定、已有短名称及精确错误，不直接改共享 helper 或混入本阶段 UI 提交。
- 关联依据：已核对 [Issue #18](https://github.com/water2004/element-skin/issues/18) 和本地 minecraft-services 文档，其中已确认的决定是角色名忽略大小写唯一；本轮读取的 issue 正文没有“最小 3 位”的明确决定，不能用大小写决议代替长度策略。官方[名称帮助](https://help.minecraft.net/hc/en-us/articles/4408950195341-View-or-Change-Your-In-Game-Profile-Name-in-Minecraft) 明确写最大 16 位；本轮未据此推导最小长度。

| 上传／删除 | 继续立即生效。有草稿时先提示保存或放弃，不自动提交、不暗中丢弃；执行及后续取列表期间锁住配置，避免刷新覆盖新的编辑。删除确认明确目标、立即生效和无法用放弃配置恢复；取消不请求，失败显示错误 |
| 读取／写入 | 普通读取不添加“提交中不能离开”的限制；写操作期间站内离开受保护。初始读取和资源刷新时字段不可编辑，避免在返回前产生被覆盖的新草稿 |

### 17.3 整页未保存提示

共享实现为 `useUnsavedChangesGuard`，由持有草稿的路由页面接入真实 dirty 和写入状态；不放一个猜测所有组件状态的全局路由拦截。现已接入首页媒体、站点设置、邮件设置、Fallback、彩蛋五个既有配置页。站点设置三组、邮件两组仍独立提交，只有对应组成功才清其未保存状态；字段在所属组写入时锁定。站点／邮件／彩蛋的“重新加载”先经过相同规则，初始读取不询问。

| 用户动作 | 有未保存修改时 | 无修改／写入中 |
| -------- | -------------- | ------------- |
| 站内菜单、链接、返回／前进等路由离开 | 弹统一确认：“放弃并离开／继续编辑”；取消或关闭确认保留字段与当前路由；确认后允许导航 | 干净时直接离开；写入中阻止站内离开并提示等待 |
| 同一组件切换对象参数 | 按离开处理，防止复用页面丢草稿 | 同上 |
| 同页查询参数或锚点变动 | 当前接入页面不因此丢弃草稿，不重复挽留 | 若未来页面会据此替换对象，需由该页面明确加入对应保护 |
| 页面“重新加载” | “放弃并重新加载／继续编辑”；确认后才重新获取替换，不预先清字段 | 干净直接加载；读取／写入期间禁止重复触发 |
| 明确“放弃更改” | 直接放弃所属草稿，不套普通导航的二次挽留 | 不能撤销服务器已成功操作；写入中不可放弃 |
| 刷新、关闭标签／窗口、地址栏输入新地址、普通整页链接 | 在 `beforeunload` 触发浏览器原生离开提示；不能提供站内自定义按钮或文案，也不能等待异步保存 | 仅 dirty 或写入时注册监听，干净及卸载后移除；写入中也只能提示，不能阻止用户强行离开 |

确认弹窗去重。确认离开本身不立刻清字段，因为后续权限或其他路由守卫仍可能取消导航；实际离开卸载后才结束本轮状态。任何路径都不在卸载时自动提交，不通过持久化密码、验证码、外部凭据恢复页面。

浏览器原生提示需用户先与页面交互，文本由浏览器决定；移动端系统强杀应用、崩溃等情况不能保证触发。因此它是丢失提醒，不是可靠保存机制。依据：[MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)；站内可等待确认并取消路由的依据：[Vue Router 导航守卫](https://router.vuejs.org/guide/advanced/navigation-guards.html)。本轮使用现代浏览器的 `preventDefault()`，不新增旧浏览器兼容分支。

现有身份提供方、OAuth 应用、个人资料等页面的离开保护及多请求结果表达仍按第 15 节推进；本节不把它们记为已迁移。即时提交的角色／材质详情不添加整表“放弃”语义，其逐项 pending、失败恢复和固定请求对象仍属既有待办。

### 18.2 左偏原因与影响范围

根页面 `appearance.css` 已使用 `scrollbar-gutter: stable` 为经典滚动条预留空间。Element Plus 的 `useLockscreen` 在检测到页面溢出时会再向 body 写入 `width: calc(100% - 滚动条宽度)`。应用原有 `width: auto !important` 仅覆盖 `el-popup-parent--hidden`：普通 Dialog 和 Drawer 使用它，但 MessageBox 使用 `el-message-box-parent--hidden`、ImageViewer 使用 `el-image-viewer-parent--hidden`，两类被遗漏，因而重复扣宽，改变页面内容的可用宽度与居中位置。

## 24. 3.5 动画统一实施与待验收清单

### 24.1 首页共同入场

标题、副标题、按钮整体位移及按钮文字使用同一 is-entered 状态。会话确定后先给初态两次 RAF 绘制机会，再整组进入；删除按钮独立的 Transition appear。刷新与站内返回走同一条路径；会话较晚完成时不让文案先播放完，失败也能进入终态。不等待头像、通知、站点配置或背景媒体返回；进入后登录状态变化只更新操作，不重播整组。

位移作用于普通流式 hero-content，只对文案容器和按钮文字做透明度过渡，不给玻璃按钮及祖先加透明度，不改玻璃伪元素、圆角或尺寸。悬停与键盘聚焦保留轻量反馈；首页唯一 fixed 层仍是背景画布。

### 24.2 全局入场与普通操作

共用 motion tokens：控件反馈 120ms、常规过渡 180ms、内容入场 320ms、卡片／首页展示入场 400ms；内容位移 8px、卡片 12px，显式交互卡片反馈为 2px。独立卡片错峰 30ms，最多累计 120ms，避免后排内容长期不可见。

Element Plus 时长和 Tailwind 默认过渡接入同一组变量；认证页移除独立的 duration-300，避免启用减少动态效果时仍留下固定过渡时长。

fadeIn／cardSlideIn／slideUp 关键帧收为一处 contentEnter；animate-slide-up 调用迁移为 animate-fade-in，不留旧别名。backwards fill 仅覆盖延迟，不让结束后的动画占用 hover transform；入场使用 translate。整页已入场时不叠加子卡片入场，个人资料卡片与公共分页删除重复动画。

移除 hover-lift 及全部调用。普通按钮、表单项、资料头像、角色／材质编辑图标和权限标签不再装饰性上浮、横移、放大或旋转；必要颜色／背景／边框／阴影／透明度反馈限定明确属性，清理 transition: all。顶栏不添加位置／宽度过渡，菜单居中的布局 transform 保留。

角色／材质可点击卡片与显式 hoverable 卡片保留轻微反馈，阴影属性语义不变。第 12.6 节的 4px 是 3.3 当时的预期，本批距离统一为 2px。首页媒体排序 TransitionGroup 和拖动反馈保留。

### 24.3 减少动态效果及边界

prefers-reduced-motion: reduce 时，界面 motion 时长、位移和错峰归零，入场动画取消并保持不透明终态。首页尚未完成会话协调时文案也可见，实际会话操作就绪后显示；不会因隐藏初态永久不可见。拖动取消装饰缩放，排序仍可完成，加载状态与提交禁用仍可辨认。

不以全局 transform: none 破坏导航居中、拖拽坐标或其他布局，不取消必要加载反馈。WebGL 自动旋转、首页媒体播放与彩蛋属于持续动画来源，本批不改变其播放行为；skinview3d 只保留初步计划。未提前实施 3.6 或阶段 4。

### 24.4 自动验证口径

HomeView 用可控 RAF 验证初态、会话提前／延后／失败、共同进入、返回首页、卸载取消及操作切换不重播；实际组件 CSS 验证文案和按钮文字透明度、父容器无透明度遮挡及共用位移。CSSOM 测试激活实际 reduce 媒体查询规则，验证可见终态、加载与禁用保留、嵌套卡片不重复入场和布局定位 transform 不被清除。JSDOM 不执行真实绘制，这些检查不代替用户的动效／毛玻璃视觉验收。

## 25. 刷新入口取舍与字段未保存标记实施方案

2026-10-26。用户要求完善研讨方案并确定实施阶段。本节给出后续实施范围、顺序和完成条件；本轮只完善文档，没有删除按钮、修改加载流程或增加字段样式。第 24 节的人工样本及原始勾选保留，不因此标为已修复或已验收。

### 25.1 背景、目标与非目标

当前页面普遍使用“刷新”表示不同动作：重新取一份只读列表、查询外部审核结果、覆盖本地配置草稿，或读取已自动更新的状态。按钮的 loading 呈现也有差异，空态在刷新中被卸载会造成闪烁甚至容器收缩。站点设置已按组显示“有未保存更改”，但缺少具体字段的定位信息。

目标是让每个保留入口具有明确范围与结果，取消无独立用途的常驻按钮；刷新时保留已有内容与稳定布局；让用户知道哪一组、哪个字段尚未保存。浏览器刷新仍可使用，但不作为局部取数或配置重载的替身，也不额外造一个调用 location.reload 的站内按钮。

非目标：不统一给各页添加骨架，不靠延长动画／固定请求延时掩盖闪烁，不新增全站草稿持久化、自动保存或字段级服务器保存，不改变设置按组明确提交的设计，不新增后端接口、数据库或权限。首页媒体的父页面草稿、资源立即操作及部分保存成功边界继续保留；Webhook 本地 stash 与 skinview3d 不纳入实施。

### 25.2 动作语义与入口清单

| 动作 | 明确语义与基本行为 |
| ---- | ------------------ |
| 浏览器刷新 | 整页重新初始化。保留既有离开保护；有草稿时由浏览器显示原生提示，不能承诺自定义提示文案。当前仅在页面内持有的筛选等状态可能重置。 |
| 更新列表／更新状态 | 重新读取指定只读资源，保留当前查询条件、既有内容与合理的滚动／选中状态；不重新挂载整个页面。手动更新默认重取当前页，筛选／每页数量改变才作为新查询回到第一页。游标明确失效时提供“回到第一页重试”，不把普通错误当作空结果或静默跳页。 |
| 重新加载配置 | 从服务端读取最新配置并替换页面草稿。未保存时沿用“放弃并重新加载／继续编辑”确认；写请求进行中保护操作。成功读取的组更新其基线，失败的组保留原值及未保存标记，不宣称所有组都加载成功。 |
| 放弃更改 | 若入口存在，恢复最近确认的本地已保存基线，不隐含读取服务端最新值，不回滚已成功的服务器写入。 |
| 重试 | 出现在明确失败的资源区域，重试对应读取；保留用户已输入条件和可用内容，不等同于重载整页。 |

针对当前入口确定以下实施目标，实际移除安排在阶段 4 数据更新规则落实后，不能先删除而使用户失去取新数据的路径：

| 页面／区域 | 最终入口取舍 | 原因与实施前提 |
| ---------- | ------------ | -------------- |
| 站点设置、邮件设置、彩蛋配置 | 保留，统一明确为“重新加载配置” | 显式覆盖草稿，使用原 dirty／busy／离开保护；不因窗口重新获得焦点而自动覆盖配置。 |
| 通知中心 | 保留局部“更新通知” | 通知可能由外部新增；更新保持当前全部／未读范围和有效的选中详情，空结果刷新保留已确认空态。 |
| 管理用户、角色、材质、邀请码、通知公告 | 保留一个“更新列表” | 多人管理、外部使用、定时状态变化有局部取新的价值；不因按钮常见就复制到其他页面。 |
| 管理端第三方应用 | 保留更新入口，明确当前权限下覆盖的应用／授权范围 | 外部申请与授权会变化；各资源失败分别反馈，保留筛选，不能一个总 loading 掩盖其他区域状态。 |
| 个人第三方应用：开发者区 | 保留“更新状态” | 审核由其他人员进行，本页需要按需查看结果，保持该区更新独立。 |
| 个人第三方应用：已授权区 | 移除常驻刷新 | 进入页面、重新返回该页、撤销成功、外部授权流程返回后重新读取；回到前台时按阶段 4 的统一过期策略检查只读数据。上述触发与错误重试落实后再移除。 |
| 仪表盘 Fallback 状态 | 移除重复的常驻手动刷新，保留自动更新与失败重试 | 当前已有倒计时自动更新；该操作只是读取状态，不是触发后端立即健康探测。显示更新状态／时间，避免用“立即检测”误导。 |
| 公共皮肤库、个人角色、衣柜等当前无独立刷新入口的页面 | 维持无常驻按钮 | 沿用进入页面、参数改变及操作完成后的数据更新，不为视觉统一补按钮。 |

只读页面返回前台时的过期判断、去重与请求间隔在阶段 4 的共享读取策略中统一定义，不散落到页面定时器；不将该行为推广为配置草稿自动重载。各项仍按细粒度权限展示和请求，不扩大数据访问能力。

### 25.3 保留刷新入口的加载展示

带文字的更新／重新加载按钮保留操作文字，在原图标位置切换为单个加载图标；按钮宽高、工具栏布局及焦点位置稳定，不再叠加两个图标，也不短暂只剩无文案按钮。执行中防止重复触发，并表达 busy／disabled 状态；减少动态效果时仍可辨认正在更新。

样本 01 的材质管理页取消独有的固定 8 张手写骨架，沿用同类卡片列表的局部加载提示与稳定内容容器，删除无调用方的骨架状态／样式；不将这套特例推广全站。该局部展示补正安排在当前 3.5，仍使用页面现有 loading，不提前引入阶段 4 的读取架构。

通过现有 UiButton 的单一实现表达此规则，迁移相关调用并清理业务页散写的 Refresh 加 loading 组合，不另外新增一套刷新按钮实现。无文字的图标按钮保留原尺寸及可访问名称。其他提交按钮的状态按其操作语义验证，不能为修刷新按钮而无差别改掉所有按钮行为。

请求生命周期分为首次尚无结果与已有结果后的更新。首次加载按页面用途给出稳定占位；已有列表或已确认空态在更新期间保留，局部显示正在更新，成功后替换内容，失败保留旧内容并显示错误／重试。空列表刷新不卸载高度支撑内容，不让相邻卡片随之跳动，不重放整页或既有卡片的入场。响应、参数改变和卸载的竞争由阶段 4 统一协调，而不是仅给 el-empty 换一个条件后宣称全站完成。

### 25.4 分组与字段未保存提示

分组 DirtyTag 保留；字段提示补充定位，两层共用同一保存基线。首个样板为 AdminSettings 的基础、安全、认证三组，涵盖文本、数字、开关、单选与折叠内字段。

确定的默认呈现为：字段标签旁的紧凑“未保存”文字，加整条表单项的细提示线／轻量底色；输入控件保持原有边框与焦点／校验状态。状态不只靠颜色表达；深浅主题可读，标记显隐不改变控件宽高或列布局，不增加上浮、逐字段入场或持续闪动。开关、单选和数字控件也在表单项层表达，不只处理文本框。折叠内字段未保存时，外部组提示仍保留，不自动展开干扰编辑。

复用 DirtyTag，增加紧凑字段呈现，原分组用法不变；字段外观使用一处公共状态样式，不让业务页面各自覆盖控件边框。数据仍归页面和现有 useDirtySnapshot：扩展该抽象以提供字段是否变化的查询，分组标记、字段标记与离开保护读取同一个基线，不再平行维护第二套 savedSettings 或逐字段快照。

字段状态约定：

- 最近一次成功加载／确认保存的业务值作为基线；首次尚未加载不显示未保存。聚焦、失焦或曾经编辑过不等于未保存。
- 当前可提交值与基线不同才显示；改回原值立即取消。归一化沿用各字段已有业务规则，不为 dirty 比较擅自 trim、改类型或改变数组语义。
- 保存成功后仅推进对应组的基线；失败不清标记，其他组草稿保持。重载或多请求流程部分成功时，只推进已确认成功的范围。
- 校验错误与未保存是两个状态，分别表达，错误／焦点优先级不被提示样式覆盖。密码等敏感值不通过标记回显旧值。
- 即时生效的对象编辑不套用“等待统一保存”的字段提示；尚在执行或失败的单次操作沿用其 pending／错误语义。

推广顺序为站点设置样板、邮件与彩蛋配置，再按 3.6 既有登记核对其他表单。Fallback 数组／白名单、首页媒体条目与资源操作单独成批，不直接套用普通平面对象字段比较；首页媒体已有条目级 dirty 保留。本节不取代 3.6 原有 hash 展示、页头、移动表格和详情交互推广任务。

### 25.5 确定的实施阶段与提交顺序

| 阶段／独立批次 | 实施范围 | 完成条件 |
| -------------- | -------- | -------- |
| **当前 3.5 收尾** | 材质管理移除独有的固定 8 张手写骨架，改用同类列表局部加载展示；修样本 01 的入场交接，保留独立卡片入场、头像例外与减少动态效果 | 不再出现亮色大块骨架突现及骨架退出后的整片隐藏交接；旧骨架状态／样式清理，用户复验；不删除刷新按钮绕过问题。原普通操作／顶栏未勾选项仍如实保留。 |
| **3.6：按钮状态推广，独立提交** | 落实 25.3 的共享按钮呈现，先通知与个人第三方应用样板，再推广保留的刷新／重载入口 | 单图标、文字和尺寸稳定、防重复触发、焦点与禁用可辨；清理被替代调用。只统一呈现，不在本批删除入口或建设请求架构。 |
| **3.6：设置未保存样板，独立提交** | 扩展已有 dirty／DirtyTag；站点设置先实施字段定位，再分批推广邮件／彩蛋等 | 改值／还原、分组保存、失败及部分成功的标记精确；离开／重载保护不回退；用户验收深浅主题与窄屏。 |

| **阶段 4：入口裁剪与更新时机，分批提交** | 落实进入／返回／操作成功后的更新和失败重试，按 25.2 移除已授权区及重复状态刷新，明确其余按钮文案与范围 | 移除后仍有可靠取新数据路径；筛选、分页和有效详情保留；浏览器刷新及未保存保护正常；按清单登记实际完成与例外。 |

顺序确定为 **3.5 收尾 → 3.6 两类独立样板／推广 → 阶段 4 先稳定读取状态、后裁剪冗余入口**。3.5 不承担新增字段标记或全面刷新架构；3.6 不先删按钮；阶段 4 不把删除按钮当作闪烁修复。新发现的确切回退按来源定点修复，不为阶段划分故意留错。

### 25.6 工程与人工验收

工程测试覆盖共享按钮的图标数量、文字可见性、尺寸约束、busy／disabled、重复点击；dirty 覆盖同值、改值再还原、未加载、成功、失败、分组与部分成功基线；读取流程覆盖快速／慢速、空／非空、失败、重复请求、参数变化、卸载与响应乱序，并断言具体 DOM、事件参数和状态。API 契约保持原样；前端构建与相关回归必须通过，不为文档变更重复跑产品全量测试。

用户人工验收分别核对四个已登记闪烁样本、深浅主题、桌面／窄屏、键盘聚焦和减少动态效果；确认按钮标签和刷新范围、空态／容器稳定、未保存字段可定位及分组保存边界。原始通过记录不改写，新增批次另列验收，不代勾，不通过统一加大最小高度掩盖状态卸载。

### 25.7 数据、API 与待确认事项

没有后端模型、数据库、API、权限或浏览器持久化格式变更；新增状态均为当前页面的客户端展示／请求状态。若阶段 4 后续需要真正的服务端主动刷新接口，需另行设计，不能把现有读取状态接口描述为立即探测。

本方案已确定阶段、默认入口清单、状态原则和样板顺序，不需要在实施时重新询问是否统一改为浏览器刷新。具体颜色强度、间距和最终动效以对应批次用户视觉验收为准；共享读取策略的过期阈值在阶段 4 统一实现时确定，不在 3.5／3.6 分散写入。原已批准的分批本地提交、不推送、用户亲自视觉验收及 Webhook stash 冻结约定继续有效。
