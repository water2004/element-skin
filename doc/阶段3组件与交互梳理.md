# 阶段 3 组件与交互梳理

日期：2026-10-24。分支：`feat/frontend-session-store`。源码基线：`1389b9d`。

状态：3.1 源码盘点完成；3.2 工程和用户人工验收通过，见第 11 节；3.3 基础组件语义与通知页样板按用户要求完成条件闭环，保留卡片阴影尚未完成人工确认等明确限制，见第 12 节；3.4—3.6 尚未实施。视觉验收由用户亲自执行，静态检查不等于页面行为或视觉已经验收。按用户“一批一个提交”的要求，3.1、3.2、3.3 各自独立本地提交，不推送。

## 1. 背景、目标与边界

阶段 2 已闭环，保留首页入场偶发不同步、自定义头像异步补入、全站弹层交互未统一三项边界。阶段 3 负责设计变量、组件语义、关闭与表单生命周期、动画；阶段 4 负责远程数据的加载、空结果、错误、刷新、重试与竞态。

本阶段目标：同类操作采用一致的视觉和行为，业务差异有明确归属；复用现有组件，移除被替代实现，而不是为每个 Element Plus 控件增加包装。

非目标：替换组件库、重做页面信息架构、修改 API 或数据库、调整权限模型、引入持久化草稿、实现清除头像入口、恢复 Webhook stash。自定义头像沿用用户已接受的异步补入策略。公共组件变更对现有调用方的影响仍需检查，但 Webhook 编辑器不纳入迁移范围。

3.1 只确认源码现状、规则建议、例外和迁移顺序；不将后续规则描述成当前产品已经具备的能力。

### 3.1 盘点时的来源（3.2 实施后职责见第 11 节）

| UI／业务组件样式                                                                 | 局部圆角、阴影、渐变、间距和控件内部覆盖                               | 共性进入组件或变量；业务特有尺寸留在所属组件               |

### 3.2 3.2 要落实的变量分类

| 分类       | 使用语义                                                                   | 收敛方式                                                                      |
| ---------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 颜色       | 页面／容器／浮层、正文／次要／禁用、边框、主要操作、成功／警告／危险、焦点 | 继续采用既有 `--color-*` 体系，建立与 `--el-*` 的明确映射；同一颜色不双向引用 |
| 间距       | 页面边距、卡片内容、表单行、操作区间隔                                     | Tailwind 标准刻度优先；仅重复的组件契约使用专有变量                           |
| 圆角与阴影 | 控件、卡片、弹层、预览区                                                   | 按组件角色归类，减少业务页面逐项覆盖，不把所有容器强制设为同一圆角            |
| 尺寸与文字 | 紧凑／默认／大控件、图标按钮、标题与辅助文字                               | 对齐现有使用场景，明确实际点击区域和内容尺寸                                  |
| 状态       | hover、active、focus-visible、disabled、loading、selected、error           | 同一状态跨深浅主题保持可辨识；禁用／加载状态不触发悬停位移                    |
| 动画       | 控件反馈、弹层开合、页面入场、首页入场                                     | 时长／缓动／位移分开定义；具体数值在样板阶段通过用户视觉验收确定              |

源码已确认的例子：UiButton 写死多组渐变和阴影，UiSegmented 有暗色硬编码，PageHeader 写死图标底色，UiCard 声明 `shadow` 属性但自己的 CSS 仍设置阴影。后续需让组件公开语义与实际渲染一致。权限标签的分类色属于业务信息编码，应集中维护色系，不能压成统一主色。

### 4.2 拟定组件交互契约

以下为职责约定，具体属性名在 3.3／3.4 实现时确定，当前不新增一套并存组件。

| 交互概念                          | 提供方                      | 执行方                                               |
| --------------------------------- | --------------------------- | ---------------------------------------------------- |
| 操作意图、重要程度、图标、大小    | 业务页面／子组件 props      | UiButton 渲染状态与反馈                              |
| 是否已修改、初始表单、当前记录 ID | 持有表单的页面／流程        | 既有 dirty 抽象和业务重置方法                        |
| 是否正在提交／执行关键操作        | 业务流程                    | 弹层统一保护关闭、按钮统一 loading／disabled         |
| 请求关闭及来源                    | 遮罩、Esc、右上角、取消按钮 | 共同进入一个关闭判断，不让 footer 直接绕过           |
| 成功提交后结束、步骤切换          | 业务流程                    | 明确区别于用户放弃；不重复弹未保存确认               |
| 实际关闭后清理                    | 业务数据／资源持有者        | 清表单、校验、密码、预览 URL、计时器；组件仅通知时机 |

Ui 组件不调用业务 API，不读取会话或浏览器存储；页面与流程保留权限判断和业务编排。没有新增后端 API、数据库模型或存储格式。

| 导航与只读内容     | 可关闭                                                                  | 按页面重新进入，不创建草稿                         | 数据错误显示由所属页面处理                                |

| 多步骤流程         | 退出整个流程判断 dirty；前后步骤切换不触发放弃                          | 步骤内保留；退出后清理整个流程数据与凭据           | 保留合法步骤与选择，不强制从头开始                        |
| 父页面草稿局部编辑 | 关闭返回父页面，不清父页面草稿                                          | 父页面负责保存／放弃与离开判断                     | 父页面保留未保存状态                                      |
| 即时操作型详情     | 可以关闭浏览；涉及明确提交中的操作时按该操作保护                        | 已成功修改保持；不能许诺取消后回滚服务器           | 显示哪次操作失败，不能显示为已保存；请求协调在阶段 4 收敛 |
| 危险确认           | 禁止遮罩误触关闭；Esc／取消只表示取消，不能触发提交；关键提交中保护关闭 | 每次重新确认，不保留确认文字                       | 保留清晰失败信息，由用户明确重试                          |

`destroy-on-close` 只负责弹层内容节点生命周期，不等于父页面的 ref／reactive 被重置。默认不持久化表单，密码和验证码不写入持久化存储。普通数据加载状态也不自动等同于禁止用户退出的关键提交状态。

### 5.3 MessageBox 与跨页表单

19 处 confirm 分布于首页媒体删除、身份提供方删除、邀请码删除、公告删除、OAuth 应用管理、角色／纹理删除、用户与权限管理、身份解绑、OAuth 应用权限确认、正版同步／解绑、皮肤／披风清除、衣柜删除等流程。2 处 prompt 用于 OAuth 管理和身份标签修改。3.4 逐处核对确认／取消文案、关闭来源和取消结果，不把用户取消当作请求失败；不需要复制一套 MessageBox 外观实现。
