## 3 本合并批的共同定义

原 3.6.2 个人角色、3.6.3 材质详情、3.6.4 公共布局合并交付，覆盖公共皮肤库、用户衣柜、用户角色、管理材质、管理角色的卡片及详情。后续仍从 3.6.5 编号继续。

### 3.1 信息与组件

- **el-tag 目前确认用于适用模型、px 精度和正版状态**。接口 `slim` 展示 Alex，`default` 展示 Steve；皮肤不额外写“皮肤”，披风展示“披风”。模型选择控件仍使用现有选择组，不用可点击 tag 替代。三类标签统一 `size="default"`、胶囊形及粗体，只调整这些语义组件，不覆盖全站 el-tag。
- 上传者／所有者使用用户图标与文字，日期为普通文字，收藏数保持 **爱心图标＋数字**。复用同语义组件不等于把这些信息全变成标签。
- 空材质名统一“未命名材质”。公共库／管理材质的 `name` 与衣柜的 `note` 仍遵守各自接口和作用范围，不因展示名称统一而混用数据。
- 收藏数沿用现有 `usage_count`，包含上传者的衣柜记录，不改成点赞数或角色应用次数。重复添加可能成功但未新增记录，不能盲目加一。
- Hash／UUID 按第 5 节处理。角色标识是 UUID，皮肤、披风分别为 Hash。
- **邮箱仅列入未来工作**：以后为管理材质上传者和管理角色所有者增加邮箱展示。本批不写相关前端、占位、props、查询、映射或逻辑。
- 操作复用 UiButton、UiSegmented、开关及现有动作区；布局复用 UiDialog、UiViewerLayout、CardActions 等。同类信息共享实现，页面仍负责业务数据和请求，避免一个大型条件业务组件。

### 3.2 数据模型与 API

继续使用现有 Texture、Profile、会话 permissions 和接口返回字段。材质身份按 Hash＋类型，角色身份按 UUID／profile ID，不以名称定位。展示组件接收 props、emit 意图，不调用业务 API；不增加服务端字段、搜索参数、持久化草稿或另一套存储路径。

**泛光已选范围**：用户已选择[按钮清单](用户侧按钮应用与泛光候选清单.md)中的 A 主要提交／创建及 B 指定次要业务动作，31 处声明显式启用（含原公共库两处）。B 的绑定／同步绿色、导入橙色、头像等蓝色按旧基线核对；工具导航、危险动作和独立视觉场景不推广，保留第 12.14 节反馈来源。

**卡片 px 角标规则（本轮追加确认）**：读取原图实际宽高后，仅在能够确认精度不为 1 倍时显示，标准精度、读取中／失败及无法判定的布局不显示角标。皮肤的 64×64 和旧版 64×32 均为 1 倍；披风的 64×32 和裁剪布局 22×17 均为 1 倍。128×128／128×64 皮肤、128×64 披风、44×34 裁剪披风等才显示角标。不能只用图片宽度是否为 64 判定。

角标位于预览右上，容器使用 flex 消除行盒基线偏移，上／右均内缩 8px。曾按卡片 16px 圆角、1px 边框和胶囊 10px 半径计算同心定位为 5px；用户视觉反馈过近，因此采用更宽的等距留白。使用 el-tag `effect="dark"`＋`round` 实心胶囊；仅显示真实图片宽度，例如 `128px`、裁剪高清披风的 `44px`，不写等效画布宽度、不加尺寸／倍数悬浮提示。详情保留实际 px 展示，不受“仅非标准”的卡片条件限制。模型标签统一 el-tag 的 `light`＋`round`；Alex／Steve 为蓝色、披风为绿色，除颜色和文字外使用相同外观，无新增装饰 CSS。

模型、px、正版标签由原 `small`（20px 高）调为大一号 `default`（24px 高），文字统一粗体；不使用 `large`，也不额外手写字号。正版卡片角标与详情复用 `OfficialBindingTag`，绿色 `success`＋`dark` 实心胶囊；卡片位置沿用 px 的 8px 等距留白，仅在拥有读取能力且绑定数据成功加载、确认有绑定时显示。加载中／失败／无权限不显示过期正版角标，详情保留对应读取状态。

精度判断参考本项目材质接收规则及 [skinview-utils 的缩放计算](https://github.com/bs-community/skinview-utils/blob/master/src/process.ts)：裁剪布局改变画布大小，不意味着像素密度改变。后台接受范围与渲染器识别范围仍不完全相同，本轮不改后端格式验证。

| 管理角色 | 角色名 → 所有者 → 角色 UUID、皮肤 Hash、披风 Hash | 清除皮肤／清除披风并列；删除角色单独分组。 |

角色详情中，确认没有皮肤或披风绑定时，隐藏对应 Hash 信息行与清除按钮；清除成功后原位隐藏。读取中／失败仍使用独立状态，不按未绑定隐藏。短元信息使用可换行的 inline-flex 组合，具名标识使用普通信息行。信息区不混入模型选择、公开开关或应用动作；名称编辑是保留的顶部例外。

**个人角色的正版绑定区**：标题“正版绑定”；下一行依次显示远端角色名、关联身份名称（为空时显示提供方名称）、绿色“正版”标签，允许换行；下一行显示“正版 UUID”，复用第 5 节前八字符摘要、全文浮层及点击复制；然后并列“同步正版数据”“解除绑定”，分别按原权限展示，名称草稿／写入中禁用。该区整体以分隔线与后面的通用操作区分开；这是用户指定的专属信息与命令分区，不把正版命令混到通用操作之后。确认无绑定时不留空区；加载中、失败及无读取权限分别表达，不渲染可用绑定及命令。

**弹窗正文不写交互说明段落**，尤其移除当前管理材质的常驻影响说明；必要后果保留在警告／确认弹窗。危险操作与普通操作以间距分组，不做装饰性整栏按钮，不为钉到底端制造大片空白。窄／短视口在共享壳内保证关闭和必要操作可达，系统移动端推广另见第 9 节。

## 5 Hash 与 UUID 的查看和复制

默认显示具名字段及原值前 **8 个字符＋三个英文句点**，例如 `皮肤 Hash：b6e5ac15...`。不拼首尾；短于或等于 8 字符不伪造省略。

| 入口 | 行为 |
| --- | --- |
| 悬浮／聚焦摘要 | 显示完整值浮层。 |
| 点击摘要 | 显式打开并保留同一浮层，供触屏查看；此时不复制。 |
| 点击浮层中的完整值 | 复制对应字段的完整原始值；键盘 Enter／Space 等价。简短提示“点击复制”与全文共用一个复制入口，点击提示文字也复制完整原值；成功显示“已复制”。 |
| 点击外部／Esc | 仅关闭标识符浮层，焦点返回触发入口，不穿透关闭详情。 |

浮层复用 Element Plus 现有组件与默认外观；可停留、选中文本、按窄屏宽度折行。复制失败保留全文供手动复制；不复制字段名、省略号或装饰空格，不隐式更改 UUID 格式。未绑定显示普通“未绑定”，读取中／失败不得伪装成未绑定。

用户希望摘要及完整值加虚线下划线提示交互，但当前没有现成的虚线文字样式。Tailwind 的 `underline decoration-dashed` 无须新增手写 CSS，仍属于新增视觉规则。因此按允许降级的约定，**本批默认复用 UiButton 的 tertiary 文字外观及已有悬浮／焦点反馈**，由摘要和完整值本身承载动作；不加额外“展开／复制”按钮、箭头、图标或专用装饰样式。虚线下划线不是本批验收必需项。

## 6 保存 关闭与异步保护

完整逐操作表与保护状态表统一维护在[交互专题第 4—5 节](五类详情交互边界与权限方案.md#4-各操作的建议提交与确认规则)。名称编辑、草稿阻止其他写入、写入中禁止关闭／切换及退出层级已接受；其他操作确认强度与尚未确认的异常策略继续待审。

### 8.2 长页面顶栏吸顶研究（2026-10-27）

**本节保留 2026-10-27 的研究依据；2026-10-28 第一小批实现见第 12.11 节。** 顶栏属于 3.6.7 的共享布局和滚动可达性调整，阶段 4 的读取架构不承接此问题；移动端浏览器工具栏、安全区及软键盘的进一步适配沿用建议的 3.7 专项。

研究时源码现状（a2485e5）：`AppLayout.vue` 的 `.layout-header-wrap` 高 64px，设置背景、层级及 flex 尺寸，但普通页面没有 `sticky`／`fixed` 定位，随文档滚动离开屏幕是现有布局结果。内部 `.layout-header` 的 `position: relative` 用于导航排布，不会让整条顶栏吸顶。普通页由文档滚动，AppShell 只有最小高度；分支基线 `39f4bb1` 的普通页同样没有顶栏吸顶规则，不能据此判定为本轮卡片整理引入的回归。

目标是普通长页面向下滚动时，顶栏持续位于**屏幕顶部**，桌面导航、窄屏菜单入口、通知、主题与账号操作保持可达；不增加滚动隐藏／缩小顶栏等新交互。首页是一屏流式布局，保留其透明顶栏与既有首页约束；认证页继续按当前规则不显示顶栏。

实施时优先评估保持文档流占位的 `sticky`＋顶部偏移方案，统一在共享 AppLayout 处理，不给各页分别复制规则。[W3C Positioned Layout 工作草案](https://www.w3.org/TR/css-position-3/#stickypos-insets) 将 sticky 的定位参照定义为最近祖先滚动容器的 scrollport；当前锁滚动补正在浮层期间给 AppShell 设置 `overflow: hidden`，因此必须核对其对吸顶参照和已滚动页面的影响。不能只增加 sticky 声明就认定覆盖“屏幕顶部”；若该结构不能稳定满足锁定前后行为，再评估 fixed 顶栏加同高文档流占位，保持首页例外，不直接把全站改成内部滚动容器。

同批需解决的布局边界：保留正文初始占位，防止标题、锚点及键盘聚焦字段被顶栏遮挡；沿用主题背景和导航宽度判断，核对顶栏、下拉菜单与全屏浮层的层级。尤其覆盖在页面中部打开／关闭详情、抽屉、确认框和图片预览时，顶栏不消失、不横移，已验收的滚动槽、遮罩与关闭后滚动恢复不回退。不为吸顶额外引入滚动入场动画或手写逐帧坐标计算。

验收须覆盖长／短页面、顶部／中部／底部、首页与操作页切换、深浅主题、登录状态与权限入口，以及桌面和导航断点两侧。除样式和导航回归外，需要实际浏览器滚动与浮层开关验证；现有 CSSOM 宽度测试不能代替吸顶位置验证，最终视觉仍由用户验收。实现时运行相关测试与构建，本次文档研究不沿用旧测试宣称新行为已通过。

### 8.3 页头文字 页宽与硬编码覆盖研究（2026-10-27）

用户反馈公共皮肤库与管理页的标题／副标题呈现两套外观，并询问全站页宽和最初硬编码扫描的规范化程度。源码结论是**设计变量及部分组件已有统一，页面级消费和容器规则尚未收敛**；不能将 3.1／3.2 的完成解释为全站硬编码已经清零。本节记录研究时基线；实际页头／页宽迁移和内容排布见第 12.12—12.13 节。

### 12.11 3.6.7 第一小批：长页顶栏（2026-10-28）
