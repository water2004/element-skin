## 2 协作与范围约束

- 仅在个人 ID 前缀分支开发，当前为 `lylighte/feat-frontend`，不得在 `dev` 修改或直接推送。
- 一批一个主要意图、一个英文提交；继续本地提交，不自动推送。文档整理与产品实施分开，不借整理启动下一批代码。
- **视觉验收由用户亲自完成**。工程测试、源码检查和样式检查不代替视觉通过，不由代理勾选人工清单。
- 当前分支保持前端范围，复用已有组件、API、权限与存储层；不改数据库、后端业务规则、权限目录或 API 契约。
- 优先现有外观与组件参数。当前新增样式难以接受，装饰效果允许降级；不能把使用 Tailwind 等同于没有新增视觉规则，不为统一外观再造基础组件。
- 本地 Webhook stash 保持冻结，不恢复、不迁移、不提交。`HANDOFF.md`、隐私草案及旧 reports 不混入本批；不新增验收报告文件。
- 上传继续使用弹窗。skinview3d fork、Three.js 升级及独立披风预览仅保留初步计划，不在本分支实施，也不阻塞本分支闭环。

## 3 本合并批的共同定义

原 3.6.2 个人角色、3.6.3 材质详情、3.6.4 公共布局合并交付，覆盖公共皮肤库、用户衣柜、用户角色、管理材质、管理角色的卡片及详情。后续仍从 3.6.5 编号继续。

### 3.1 信息与组件

- **el-tag 目前仅确认用于适用模型和 px 精度**。接口 `slim` 展示 Alex，`default` 展示 Steve；皮肤不额外写“皮肤”，披风展示“披风”。模型选择控件仍使用现有选择组，不用可点击 tag 替代。
- 上传者／所有者使用用户图标与文字，日期为普通文字，收藏数保持 **爱心图标＋数字**。复用同语义组件不等于把这些信息全变成标签。
- 空材质名统一“未命名材质”。公共库／管理材质的 `name` 与衣柜的 `note` 仍遵守各自接口和作用范围，不因展示名称统一而混用数据。
- 收藏数沿用现有 `usage_count`，包含上传者的衣柜记录，不改成点赞数或角色应用次数。重复添加可能成功但未新增记录，不能盲目加一。
- Hash／UUID 按第 5 节处理。角色标识是 UUID，皮肤、披风分别为 Hash。
- **邮箱仅列入未来工作**：以后为管理材质上传者和管理角色所有者增加邮箱展示。本批不写相关前端、占位、props、查询、映射或逻辑。
- 操作复用 UiButton、UiSegmented、开关及现有动作区；布局复用 UiDialog、UiViewerLayout、CardActions 等。同类信息共享实现，页面仍负责业务数据和请求，避免一个大型条件业务组件。

### 3.2 数据模型与 API

继续使用现有 Texture、Profile、会话 permissions 和接口返回字段。材质身份按 Hash＋类型，角色身份按 UUID／profile ID，不以名称定位。展示组件接收 props、emit 意图，不调用业务 API；不增加服务端字段、搜索参数、持久化草稿或另一套存储路径。

## 4 五类卡片与弹窗

### 4.1 卡片

| 位置 | 从上到下的内容 | 点击与操作 |
| --- | --- | --- |
| 公共皮肤库 | 预览 → 材质名 → **上传者、模型标签、♡ 收藏数同排** → 添加到衣柜 | 卡片预览／内容打开详情；添加是独立动作，不冒泡打开详情。上传日期留在详情，不放卡片。 |
| 用户衣柜 | 预览 → 材质名 → 适用模型标签 Alex／Steve／披风 | 卡片打开详情，无独立操作按钮，不另写“皮肤”。 |
| 用户角色 | 预览 → 角色名 → 可用的快捷操作 | 卡片打开详情；仅展示可操作的“设为头像”“清除皮肤”“清除披风”。不加模型／正版摘要，删除角色仍仅在弹窗。 |
| 管理材质 | 预览 → 材质名 → 用户图标＋上传者 | 卡片打开详情，无独立操作按钮。 |
| 管理角色 | 预览 → 角色名 → 用户图标＋所有者 | 卡片打开详情，无独立操作按钮。 |

同页卡片控制标题行数和信息高度，长名字及窄屏允许合理换行。衣柜、管理材质、管理角色及无可用快捷操作的个人角色卡片自然收尾，不保留空按钮栏；均提供可访问名称及 Enter／Space 打开能力。列表沿用静态预览，不为卡片启动交互旋转，不在可点击整卡内部嵌套无效按钮结构。

**卡片 px 角标规则（本轮追加确认）**：读取原图实际宽高后，仅在能够确认精度不为 1 倍时显示，标准精度、读取中／失败及无法判定的布局不显示角标。皮肤的 64×64 和旧版 64×32 均为 1 倍；披风的 64×32 和裁剪布局 22×17 均为 1 倍。128×128／128×64 皮肤、128×64 披风、44×34 裁剪披风等才显示角标。不能只用图片宽度是否为 64 判定。

角标位于预览右上，使用 el-tag `effect="dark"`＋`round` 实心胶囊；仅显示真实图片宽度，例如 `128px`、裁剪高清披风的 `44px`，不写等效画布宽度、不加尺寸／倍数悬浮提示。详情保留实际 px 展示，不受“仅非标准”的卡片条件限制。模型标签统一 el-tag 的 `light`＋`round`；Alex／Steve 为蓝色、披风为绿色，除颜色和文字外使用相同外观，无新增装饰 CSS。

精度判断参考本项目材质接收规则及 [skinview-utils 的缩放计算](https://github.com/bs-community/skinview-utils/blob/master/src/process.ts)：裁剪布局改变画布大小，不意味着像素密度改变。后台接受范围与渲染器识别范围仍不完全相同，本轮不改后端格式验证。

### 4.2 弹窗

桌面端左侧预览、右侧信息与操作；名称及局部改名始终在顶部。信息区之后以一条明确分隔线进入操作区。以下分组延续字段清单，具体间距和换行交用户视觉验收。

| 位置 | 右侧信息区 | 分隔线后的操作区 |
| --- | --- | --- |
| 公共皮肤库 | 材质名 → px／适用模型标签 → 上传者、上传日期、♡ 收藏数 | 添加到衣柜。下载仅预留设计可能，不渲染内容。无额外 Hash 字段。 |
| 用户衣柜 | 材质名 → px／适用模型标签 → 材质 Hash | 模型选择（仅皮肤）、公开开关；目标角色＋应用按钮；删除纹理单独分组。 |
| 用户角色 | 角色名 → Alex／Steve 标签 → 角色 UUID、皮肤 Hash、披风 Hash；有数据时增加正版关联信息 | 用作头像；清除皮肤／清除披风并列；有正版关联时另列同步／解除；删除角色单独分组。 |
| 管理材质 | 材质名 → 上传者 → 材质 Hash | 模型选择（仅皮肤）、公开开关；强制下架单独分组。 |
| 管理角色 | 角色名 → 所有者 → 角色 UUID、皮肤 Hash、披风 Hash | 清除皮肤／清除披风并列；删除角色单独分组。 |

角色详情中，确认没有皮肤或披风绑定时，隐藏对应 Hash 信息行与清除按钮；清除成功后原位隐藏。读取中／失败仍使用独立状态，不按未绑定隐藏。短元信息使用可换行的 inline-flex 组合，具名标识使用普通信息行。信息区不混入模型选择、公开开关或应用动作；名称编辑是保留的顶部例外。

**弹窗正文不写交互说明段落**，尤其移除当前管理材质的常驻影响说明；必要后果保留在警告／确认弹窗。危险操作与普通操作以间距分组，不做装饰性整栏按钮，不为钉到底端制造大片空白。窄／短视口在共享壳内保证关闭和必要操作可达，系统移动端推广另见第 9 节。

## 5 Hash 与 UUID 的查看和复制

默认显示具名字段及原值前 **8 个字符＋三个英文句点**，例如 `皮肤 Hash：b6e5ac15...`。不拼首尾；短于或等于 8 字符不伪造省略。

| 入口 | 行为 |
| --- | --- |
| 悬浮／聚焦摘要 | 显示完整值浮层。 |
| 点击摘要 | 显式打开并保留同一浮层，供触屏查看；此时不复制。 |
| 点击浮层中的完整值 | 复制对应字段的完整原始值；键盘 Enter／Space 等价。简短提示“点击复制”与全文共用一个复制入口，点击提示文字也复制完整原值；成功显示“已复制”。 |
| 点击外部／Esc | 仅关闭标识符浮层，焦点返回触发入口，不穿透关闭详情。 |

浮层复用 Element Plus 现有组件与默认外观；可停留、选中文本、按窄屏宽度折行。复制失败保留全文供手动复制；不复制字段名、省略号或装饰空格，不隐式更改 UUID 格式。未绑定显示普通“未绑定”，读取中／失败不得伪装成未绑定。

用户希望摘要及完整值加虚线下划线提示交互，但当前没有现成的虚线文字样式。Tailwind 的 `underline decoration-dashed` 无须新增手写 CSS，仍属于新增视觉规则。因此按允许降级的约定，**本批默认复用 UiButton 的 tertiary 文字外观及已有悬浮／焦点反馈**，由摘要和完整值本身承载动作；不加额外“展开／复制”按钮、箭头、图标或专用装饰样式。虚线下划线不是本批验收必需项。

## 6 保存 关闭与异步保护

完整逐操作表与保护状态表统一维护在[交互专题第 4—5 节](五类详情交互边界与权限方案.md#4-各操作的建议提交与确认规则)。名称编辑、草稿阻止其他写入、写入中禁止关闭／切换及退出层级已接受；其他操作确认强度与尚未确认的异常策略继续待审。

已确认名称草稿阻止其他写操作、写入中禁止关闭和切换；名称按需编辑／显式保存方案也已获同意：点击名称或编辑入口才显示保存／取消，失焦保持草稿，保存或 Enter 提交，取消仅退出本字段。它不将整个详情改成统一保存，也不影响站点设置等原有组级保存。用户本轮已接受专题第 5.1 节退出对照：显式取消／X 放弃所属范围，遮罩／外层 Esc 有草稿时确认，内层 Esc 不穿透；已有服务器修改不回滚。其他操作的确认强度仍待审，写失败、超时结果不明与写成功但刷新失败分别反馈。

防串记录、正确对象和真实结果属于本批正确性；全站读取架构仍留阶段 4，不借本批宣称已解决跨用户并发覆盖。

## 7 必须继承的业务事实

### 7.1 权限

现有细粒度校验继续保留，完整读取／操作矩阵见[交互专题第 3 节](五类详情交互边界与权限方案.md#3-权限分三层核对)。页面入口、对象读取及写权限分开；只写无读不等于能展示详情，个人与管理范围不互相冒充。

本轮发现衣柜更新存在“先提交写入、再因缺少读取权限返回错误”的后端路径，单列于专题第 7.2 节。本分支不改后端，也不把前端禁用称为该契约问题已修复。

### 7.2 删除与材质归属

清绑定不删材质，删除角色保留衣柜；个人删除可能按库原上传者分流，管理下架保留角色绑定、头像及文件。准确影响与限制统一见[交互专题第 7 节](五类详情交互边界与权限方案.md#7-后端契约限制与单列问题)，归属完善继续由 [Issue 22](https://github.com/water2004/element-skin/issues/22) 独立跟踪。本批不拆出实际同接口的虚假移除／删除按钮。

### 7.3 正版绑定

总体方向仍为“手动同步、本地可编辑”：本地操作不自动回写远端，解除关联保留本站角色；同步可能覆盖材质及模型，采用接口实际结果。信息与动作清单见第 4 节，具体覆盖确认、解除／删除后果及操作保护见[交互专题](五类详情交互边界与权限方案.md)，仍待逐项审查。

## 10 阶段 4 读取状态与刷新入口

阶段 4 先统一生命周期，再裁剪冗余入口：区分首次未取得结果、已确认空态、已有内容更新、失败；更新时保留可用内容和稳定布局，失败不伪装成空结果。统一参数变化、去重、取消、响应顺序、缓存失效、后台更新及操作后取数，不在页面散布另一套定时器。

优先处理已登记的通知空态消失、个人第三方应用开发者区及已授权区刷新收缩／临时内部滚动条。管理材质的大块亮骨架问题已由 3.5 处理，不再推广该骨架；按钮本身呈现先由 3.6.5 处理。

| 页面／区域 | 最终刷新入口方向 |
| --- | --- |
| 站点、邮件、彩蛋配置 | 保留“重新加载配置”，明确覆盖草稿；有未保存内容先确认，失败组保留输入与基线，不因回到前台自动覆盖。 |
| 通知中心 | 保留局部“更新通知”，保持筛选与有效详情。 |
| 管理列表与第三方应用 | 保留明确范围的更新入口，资源区独立反馈。 |
| 个人应用开发者区 | 保留“更新状态”，用于查看外部审核变化。 |
| 个人应用已授权区 | 补齐进入／返回／撤销成功／外部授权返回后的更新及失败重试，再移除常驻刷新。 |
| 仪表盘 Fallback 状态 | 沿用自动更新及失败重试，再移除重复手动刷新；读取状态不是触发后端立即健康探测。 |
| 公共库、个人角色、衣柜 | 维持无常驻刷新按钮，保证进入、参数变化和操作后的更新。 |

浏览器刷新保留整页初始化能力及适用的原生离开提示，不新增站内 location.reload 按钮，也不替代有明确草稿语义的配置重载。过期阈值和后台更新策略在阶段 4 统一确定；这些入口不得先删后补更新路径。
