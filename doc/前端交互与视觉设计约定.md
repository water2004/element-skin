# 前端交互与视觉设计约定

适用项目：Element Skin。本文是前端交互与视觉设计的持续维护参考，不替代 API、权限或数据契约。

本文按设计问题组织，覆盖信息、动作、草稿、退出、权限、读取状态、异常反馈及布局。实现优先复用[共享组件约定](../element-skin/src/components/README.md)和[设计变量](../element-skin/src/assets/styles/tokens.css)。

**设计要求不等于全站实现或验收声明。** 下文说明共享入口、适用范围和需要业务流程明确的边界；读取架构及移动端等要求仍需逐页落实。进度、验收、扫描和待办记录不属于本文内容。

## 1 目标 非目标与维护方式

目标是让同一种信息、动作和状态在不同位置有一致含义，让用户知道“正在看什么、修改何时生效、关闭会丢什么、失败后还有什么”。复用组件服务于这种一致性，不追求所有页面完全相同。

前端设计不得自行重新定义材质归属、服务端授权、角色命名策略、数据删除级联或并发条件写。若方案依赖新的服务端字段或统计，先明确相应契约，不通过界面补造能力或不可靠的占位信息。

规则改变时重写现行定义，并与对应代码同步维护；历史过程留在开发记录，不在本文并列相冲突的规范。新增页面说明采用范围和合理例外，不以共享组件存在为由宣称全部调用方已经迁移。

## 2 设计与实现的共同边界

页面拥有取数、路由、消息、命令及结果合并；子组件通过 props 接收数据、emit 用户意图。复用 API client、存储模块与会话单一来源，不在 UI 组件中建立另一套请求、权限或缓存体系。

同一种信息优先复用语义组件，例如模型、精度、身份、标识符、名称编辑；同一种操作优先复用 UiButton、选择组、开关及动作区。共享布局不应演变成一个用大量业务分支控制所有详情的巨型组件。

Tailwind 负责常规布局、间距与响应式；颜色和已有公共尺寸引用既有变量。只有复杂动画、组件内部稳定尺寸或 Element Plus 内部覆盖等才使用必要 CSS。新增装饰样式需在当批说明用途；使用 arbitrary class 也属于新增规则，不能绕过设计审查。

操作型页面保持清楚、可扫描。信息区与动作区分离，动作不会伪装成普通标签；危险程度、按钮层级与视觉强调是不同维度。

## 3 信息模型与页面内容排布

### 3.1 信息角色

| 信息类型           | 当前推荐载体                         | 应避免的表达                                         |
| ------------------ | ------------------------------------ | ---------------------------------------------------- |
| 页面标题、副标题   | 具备正确标题级别的公共页头；图标可选 | 每页自行决定字号、字重和页外距。                     |
| 对象名称           | 详情顶部名称／按需编辑组件           | 与通用操作混排，或输入框长期呈现为已可直接修改。     |
| 模型、px、正版状态 | 指定语义组件内的 Element Plus tag    | 将上传者、日期、Hash、收藏数都变成 tag。             |
| 上传者、所有者     | 用户图标＋普通文字；按空间内联换行   | 用身份标签冒充可点击用户入口，提前渲染未来邮箱占位。 |
| 收藏数             | 现有爱心图标＋数字                   | 改称点赞数，或把角色应用次数当作收藏数。             |
| 日期、一般属性     | 普通文字、内联属性组或具名两列信息   | 无标签长字符串、只靠颜色说明字段含义。               |
| Hash、UUID         | 具名摘要与完整值浮层，支持复制       | 普通可编辑输入框、铺满全文、只裁掉全文而无法获取。   |
| 当前状态           | 有明确文案的状态区／现有状态组件     | 用“空结果”代替未加载、失败或无权限。                 |

这里的 tag 限制针对材质／角色信息，不否定权限选择、审核状态等已经存在的业务标签。新的语义先确定用途，不能因 el-tag 可用就全部标签化。

### 3.2 页头 文字与页宽

普通用户页、管理页及采用 PageHeader 的授权页复用公共页头：主标题 32px／400（正常字重）／1.6 行高，副标题 16px／1.6 行高，两者间距 8px，使用已有字号与间距变量。主标题统一为 135°、`--color-heading` 到 `--color-primary` 的文字渐变；副标题使用 `--color-text-light`。首页大标题、认证卡及正文富文本标题有独立语义，不套用普通页头规则。

PageHeader 标题宽度使用 `fit-content`，最大为所在内容区宽度，让渐变以标题自身展开，避免长副标题改变相同标题的渐变分布。长标题继续换行，页面不自行复制旧 `.page-header` 规则。

按页面标题、分组标题、正文标题、正文、说明、辅助文本区分角色。PageHeader 图标可选，支持返回入口、对象元信息、主操作与独立工具栏槽；不强制用户页增加管理图标。富文本中的 h1／h2 属于文档内容，不与页面 h1 简单等同。

PageContainer 按用途提供宽度与纵向留白：form 900px 用于设置／资料，editor 1000px 用于复杂编辑／身份，wide 1200px 用于表格与混合仪表盘，gallery 为可用全宽。AppShell 外距与容器上下留白分别引用 20px 共享来源。认证卡沿用 440px、28px 标题的独立变量，授权面板沿用标准 max-w-3xl；资料内层 600px 是局部表单约束，不是另一整页宽度。

每页需要说明页头、工具栏、主体、空／错状态和分页的位置。窄屏工具栏允许换行且不压住标题；宽表可在表格区域内部横向滚动，不能让整页横向溢出。普通页面布局检查不能代替认证、授权等完整业务流程验证。

公告内容弹窗的预览具有独立滚动区，支持键盘聚焦浏览。桌面双列时，预览通过尺寸隔离从左侧表单取得高度，长预览不参与撑高网格行；窄屏上下排列时预览占半个动态视口高度。标题、摘要及 Markdown 预览均留在同一个预览滚动区，预览区标题和弹窗底部操作保持可达；短视口仍允许外层内容区必要滚动，预览内滚动到边缘时不继续带动左侧表单。不增加新路由，不改草稿、提交和清洗规则。

## 4 主题 变量与可解释的局部值

**已有变量基础，业务残留继续迁移。** 结构色优先使用 `--color-heading`、`--color-text`、`--color-text-light`、`--color-card-background`、`--color-border` 等，状态色复用 Element Plus 调色板映射。明暗主题均验证，不按截图硬写另一套黑／白常量。

当前共享值如下，作为实现参考，不代表所有局部尺寸都必须替换：

| 角色           | 基线来源与取值                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------- |
| 控件高度       | small 24px、default 32px、large 40px。                                                          |
| 圆角           | control 8px、card 16px、dialog 14px。                                                           |
| 间距           | control gap 8px、action gap 12px、content padding 16px、card padding 20px、panel padding 24px。 |
| 字号           | caption 12px、description 16px、body 15px、title 32px；认证卡标题 28px 为具名例外。             |
| 弹窗宽度       | form 500px、wide-form 1120px、viewer 800px，均受可用视口限制。                                  |
| 卡片与预览背景 | 深浅两套灰色渐变，详情预览与卡片依现有共享入口使用。                                            |

渐变是图像值，应放入支持图像的 background／background-image，不赋给 background-color。此前卡片渐变消失即源于这一类使用错误；变量存在本身不证明视觉正确。

只有相同设计角色需要同步变化时才提升为共享变量。协议状态码、UUID 分段、PNG／材质像素标准、相机位置、缓存容量和开发代理属于各自领域，不能归入一个通用视觉常量集合。稳定边框／焦点尺寸可以保留在组件内部，重复值则先判断是否同义。

## 5 按钮 选择与卡片

### 5.1 动作的层级与语义

**UiButton 已实施；部分页面尚未迁移。** `variant` 表达主次：primary、secondary、tertiary；`tone` 表达含义：neutral、primary、success、warning、danger。默认 secondary＋neutral，primary＋neutral 使用主色。创建／提交／主要应用可以突出，删除不能只因位于页底就成为默认主动作。

清除绑定是 warning 语义，删除／强制下架是 danger 语义；具体确认强度按影响范围单独决定，不能从颜色推出“所有 warning 都必须新增确认”。新的确认须结合具体操作评审后采用，不自动全站推广。

短文案保持动作明确。角色卡片空间有限可用“头像／皮肤／披风”简写，同时通过 aria-label 保留完整的“设为头像／清除皮肤／清除披风”可访问名称；这三个快捷入口不再包裹可见 tooltip。仅图标按钮必须有可访问名称，不能只靠外形或鼠标 tooltip 解释。

loading 时保持按钮原尺寸、同排布局和点击范围，阻止重复提交。UiButton 默认保留内容占位，以居中 spinner 替换内容；刷新／重载采用 `loading-mode="icon"`，只替换前置图标且保留文字。按钮状态与内容区读取状态分别设计，不能以按钮正确显示代替内容更新策略。

### 5.2 可选 hover 与 icon-swap

UiButton 的 `hover-effect` 默认关闭；主要提交／创建和指定次要业务动作显式启用。按钮自身不位移，PreviewCard 的整卡上浮与阴影保留，内部按钮随卡片整体移动，不能再叠加一次按钮位移。

个人角色卡片三个快捷按钮使用共享 `swap-icon`：头像 → Setting，皮肤／披风 → Close（X）。文字向上移出并缩至 0.8，图标从下方以 -90° 旋转进入，按钮裁切内部溢出。位移使用独立共享变量 `--motion-duration-swap: 300ms` 与 `--motion-easing-swap: cubic-bezier(0.34, 1.56, 0.64, 1)`，opacity 使用同一时长和 ease。

过渡写在文字／图标的常态规则上，**进入时图标过冲回正，退出时文字回位也过冲恢复**，不只在 hover 规则上配置动画。支持 hover 的鼠标悬浮与键盘 focus-visible 共用目标；悬浮或可见焦点仍有一个保持时不提前回位。两者均退出后回到文字常态；禁用／写入中不显示切换目标，减少动态效果下时长为 0、即时切换。保留完整可访问名称与键盘执行，不为每个按钮独写轨迹，也不把 X 解释成关闭卡片。

泛光尺寸由 `--shadow-button-hover` 保持 `0 4px 12px`；颜色在 UiButton 内按 tone 取 28% 的语义色，neutral／primary 为主色，success／warning／danger 取组件库同名颜色。绑定正版／同步正版用绿色，导入入口用橙色，头像／重新连接／应用管理／启动器用蓝色；重设邮箱常态保留中性外观，悬浮配蓝色。头像及同步恢复旧版明确指定的 primary／success，不能因为重构丢失 tone 而继续统一为灰色。

泛光仅支持 hover 且非禁用／加载时显示，键盘保留独立焦点轮廓。工具导航、破坏性动作及独立视觉场景不自动启用，danger 色源具备不等于删除入口启用。不全局覆盖 el-button。首页玻璃按钮使用独立的 hover／focus 上移效果，不套用操作型按钮的无位移规则。

### 5.3 选择与开关

互斥选项复用 UiSegmented／既有选择控件；图标、选中态和标题需表达同一选项。开关在对象详情中可作为即时命令，在设置表单中可只改变本地草稿，**生效时机由交互类型决定，不能看控件形状判断**。

邮箱域名选择是有限选项，默认选择符合当前策略的域名，不允许通过输入形成搜索／自定义值。与邮箱本地部分组成一个连贯输入区，避免 append 区内部再套完整边框。禁用文本输入和后端最终校验都要保留各自职责。

### 5.4 卡片基础

**UiCard／PreviewCard 已实施。** UiCard 的默认 shadow 为 never；显式 hover／always 才按用途显示阴影。hoverable 的位移与 shadow 是两个维度，不能靠加阴影暗示一个实际不可点击的静态容器。padding 使用 none／compact／default／spacious 的已有映射。

仪表盘统计卡／启动器卡当前均显式 hover 阴影：鼠标进入整卡后显示共享 `0 8px 24px`、黑色 10% 阴影，移出以共享 180ms 淡去，减少动态效果时即时切换。这两张未设 hoverable，也没有整卡点击跳转；这是源码事实，是否保留静态信息容器的悬浮强调仍由用户审查，不据阴影视为已经具有操作语义。

可点击卡片有明确焦点及 Enter／Space 入口，独立动作不冒泡打开详情，不嵌套无效的按钮结构。无动作时自然收尾，不保留空按钮栏。同页卡片的标题与信息高度可协调，长名称不得覆盖其他字段。

卡片使用静态预览，不为每张卡启动持续交互旋转。详情使用交互预览；两个位置的渲染策略不同，不能为追求“统一组件”而增加大量 WebGL 上下文。

## 6 五类卡片与详情的具体约定

以下定义五类卡片与详情的信息顺序和动作归属；正版绑定等特殊状态还需使用相应数据验证。

### 6.1 卡片

| 位置       | 信息顺序                                         | 操作                                                   |
| ---------- | ------------------------------------------------ | ------------------------------------------------------ |
| 公共皮肤库 | 预览 → 材质名 → 上传者、模型 tag、爱心收藏数同排 | 独立“添加到衣柜”；预览／内容打开详情。                 |
| 用户衣柜   | 预览 → 材质名 → Alex／Steve／披风 tag            | 无卡片操作栏，进入详情操作。                           |
| 用户角色   | 预览，绑定时右上正版角标 → 角色名                | 可用的头像／皮肤／披风三个等宽单行动作；删除只在详情。 |
| 管理材质   | 预览 → 材质名 → 上传者                           | 无卡片操作栏，进入详情。                               |
| 管理角色   | 预览 → 角色名 → 所有者                           | 无卡片操作栏，进入详情。                               |

个人角色快捷动作只按实际可操作项分列；没有皮肤／披风时隐藏相应清除入口，没有权限也不保留空位。不得为凑三个按钮展示无意义的禁用动作。读取尚未确认则属于等待／失败状态，不能冒充已确认无绑定。

### 6.2 详情信息与动作

左侧预览、右侧信息与动作；窄屏可上下排列，但预览不能占去主要操作的全部可用高度。名称在顶部，随后信息，再用分隔线区分操作；不在详情增加说明“此处如何操作”的长段落。必要警告保留在确认层。

| 位置     | 信息区                                                       | 操作区                                                               |
| -------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| 公共库   | 材质名、精度、模型、上传者、上传日期、爱心收藏数             | 添加到衣柜。下载仅记后续需求，当前无按钮或占位。                     |
| 衣柜     | 材质名、精度、模型、Hash                                     | 设置模型、设置公开、选择目标并应用、删除纹理。名称仍在顶部局部保存。 |
| 用户角色 | 角色名、模型、角色 UUID、有绑定的皮肤／披风 Hash；正版区另列 | 用作头像、清除皮肤、清除披风、删除角色。                             |
| 管理材质 | 材质名、上传者、Hash                                         | 修改模型、修改公开、强制下架。邮箱为未来能力，不渲染前端占位。       |
| 管理角色 | 角色名、所有者、角色 UUID、有绑定的材质 Hash                 | 清除皮肤、清除披风、删除角色。邮箱同样只记后续。                     |

空名称显示“未命名材质”。公共／管理材质的 name 与衣柜记录 note 的作用范围不同，不因中文都叫“材质名”就混用写入字段。收藏数沿用 usage_count 的既有契约，包含上传者的衣柜记录；重复添加不盲目加一。

没有绑定时隐藏对应 Hash 行和清除按钮；加载失败／无权读取不能用“未绑定”代替。普通更新、清绑定后保持详情打开，列表与预览同步；删除／下架成功才关闭正确目标的详情。卡片与详情中的同一动作调用同一业务处理，不维护第二套命令。

### 6.3 模型 精度与正版标签

| 语义 | 外观与文字                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 模型 | Alex／Steve 使用蓝色，披风使用绿色；el-tag light＋round，除了文字和颜色外外观一致。不展示 slim／default，不额外写“皮肤”。 |
| px   | el-tag dark＋round 实心背景，显示原图真实宽度如 128px／44px；不加尺寸／倍数 tooltip。                                     |
| 正版 | 绿色 el-tag dark＋round，文字“正版”，与详情共用 OfficialBindingTag。                                                      |

以上三个语义组件统一 Element Plus **default** 尺寸与粗体，不全局修改所有 tag。卡片角标上／右均内缩 8px，以 flex 消除基线偏移；圆角计算不能代替实际边缘留白和主题下的视觉验证。

卡片 px **当且仅当精度可判定且非 1 倍**时显示。标准皮肤为 64×64 或旧版 64×32，标准披风为 64×32 或裁剪布局 22×17。128×128／128×64 皮肤、128×64 披风、44×34 裁剪披风属于高精度；不能单凭宽度是否为 64 判断。标准、读取中／失败及无法判断的布局不显示卡片角标；详情可以显示标准精度，并区分加载中和未知。

### 6.4 正版绑定独立分区

位于角色信息之后、通用动作之前，结构为：

1. “正版绑定”分区标题。
2. 远端角色名、关联身份名称／提供方、正版状态标签。
3. 正版 UUID，沿用统一摘要、完整值和复制方式。
4. 同步正版数据、解除绑定两个专属命令。

无绑定不留空区，读取未完成、失败和无权限各自表达，不用过期绑定放行命令。解除正版绑定、解除关联身份、删除本地角色是不同操作；前者保留本地角色及材质和关联身份，不借 UI 文案改变接口行为。

同步为用户显式命令，按实际后端契约处理远端名称／模型／材质覆盖、远端缺值及名称冲突。前端不能承诺不存在的局部保留或自动解决冲突。管理角色当前不新增正版查询／标签。

## 7 Hash UUID与复制

**IdentifierValue 已实施。** 角色标识是 UUID，皮肤／披风等内容标识为 Hash；展示时具名，不能全部写“Hash”。原始 UUID 的连字符／大小写按接口原值保留，不为显示而改变复制内容。

默认显示前 8 字符加字面量 `...`；短值直接显示。悬浮／聚焦显示完整值浮层，点击摘要可固定展开，兼顾触屏。摘要用于展开，**点击浮层中的完整值或“点击复制”文字才复制完整原值**，两者必须同属一个动作区。

不新增多排按钮，不强制虚线下划线；当前采用已有文字按钮外观和可访问名称作为提示。全文允许换行与手动选取，复制成功有简短反馈，剪贴板失败提供完整文本手动复制的回退。

Esc／外围点击优先关闭标识符子层，不穿透关闭主详情；返回触发位置的焦点。更高层确认框拥有自己的 Esc／取消，不被下层浮层抢走。

## 8 交互类型与提交时机

对象编辑与表单是主类，但不能覆盖所有状态归属；具体流程必须明确下表中的类型。已有对象也可以刻意要求明确保存，不能仅凭“编辑对象”就改成即时写入。

| 类型                 | 草稿／写入归属                             | 成功与退出                                                 |
| -------------------- | ------------------------------------------ | ---------------------------------------------------------- |
| 对象详情逐项命令     | 每个明确动作独立提交；名称有自己的局部草稿 | 普通更新留在详情，删除才关闭；退出不能撤销已完成命令。     |
| 独立创建／编辑表单   | 字段先在本地，显式提交才写入               | 失败保留输入；成功后按该流程关闭／返回或建立新基线。       |
| 设置页分组保存       | 同一对象的各组明确保存；可存在多组未保存   | 每组成功只清该组 dirty，失败组保留；不能一次成功就清全页。 |
| 父配置草稿的子编辑器 | 子层完成只回写父草稿，不等于服务器已保存   | 退出子层只丢本子层草稿；父层仍有整体保存／放弃。           |
| 多步流程             | 中间步骤共享本轮草稿或短期流程状态         | 返回上一步不等于丢弃整个流程；完整退出才按所属范围清理。   |
| 确认命令层           | 确认后才调用目标命令，无独立长期草稿       | 取消只取消本命令，保留父详情／字段草稿。                   |
| 只读／导航浮层       | 无业务草稿                                 | 可关闭，焦点及层级恢复；不能误触发父层动作。               |

首页媒体是需要特别保护的混合：编辑、启用和排序进入父配置草稿，保存配置后生效；上传和删除立即生效。已有未保存配置时先保存或明确放弃，再执行即时命令；禁止上传后把旧草稿全量覆盖回去。该流程后续继续使用弹窗，不改为上传独立页面。

## 9 名称编辑与详情内的写入边界

**五类详情中的指定编辑入口已实施。** 常态只显示名称与前方编辑入口；点击名称或编辑按钮进入编辑，才出现“保存名称／取消”。失焦保留草稿，不发送请求，也不自动丢弃。

保存或 Enter 才提交，先校验权限、有效值、真实变更及写入锁，处理输入法组合键，避免 Enter／Esc 错触发。只进入编辑但值没改变不制造脏状态；字段校验与是否允许空值依具体字段契约，不由通用组件猜测。

真实名称草稿存在时阻止其他业务写操作，包括模型、公开、应用、清绑定、头像、同步、解除及删除等；预览与查看／复制仍可用。用户先保存或取消名称，再执行另一个写动作。保存失败保留草稿与错误，成功更新确认值并退出字段编辑。

字段“取消”及字段内 Esc 只放弃本字段，保留主详情；不能等同主详情关闭。输入法组合期间 Esc／Enter 不穿透主层。对象切换要经过草稿退出保护，不能让旧对象名称写到新对象。

## 10 退出 取消与离开页面

### 10.1 当前已确认的退出层级

**UiDialog 与详情样板已实施；全站流程仍需逐项接入。**

| 入口                       | 无写入进行时的行为                                                         |
| -------------------------- | -------------------------------------------------------------------------- |
| 字段取消／字段内 Esc       | 放弃本字段草稿，回到本对象详情，不关闭详情。                               |
| 主弹窗明确“取消”或右上 X   | 直接放弃本弹窗拥有的草稿并关闭，不重复询问。名称取消按钮不属于主弹窗取消。 |
| 主弹窗遮罩／外层 Esc       | 无修改直接关闭；有本层未保存修改时询问是否放弃。继续编辑则保留输入。       |
| 业务命令确认的取消／X／Esc | 仅退出该确认，父层保持原状态。                                             |
| 标识符等子浮层外围／Esc    | 先关闭子浮层，不穿透父层。                                                 |
| 切换详情对象               | 名称有草稿先确认放弃，保留则不切换；无草稿可切换。                         |
| 页内路由离开／重载配置     | 存在未保存修改时明确询问范围；继续编辑阻止原操作。                         |

写入中禁止用户关闭、切换对象、重复命令和受保护的站内离开／配置重载。确认框尚未结束时去重，不同时堆叠多个放弃询问。程序在成功后设置 visible=false 是流程控制，不应被当作一次新的人为取消；调用方必须遵守已确定的成功路径。

关闭后的清理要核对生命周期，旧 closed 回调不能清掉快速重开的新表单。子层范围和父层范围必须在组件参数、事件及流程中一致，不能共用一个含义模糊的“取消”。

### 10.2 浏览器离开边界

刷新、关页签、地址栏输入新地址等不能使用站内自定义确认替代浏览器提示。dirty／busy 时通过既有 beforeunload 申请原生离开提示；具体是否展示与文案由浏览器控制，不能保证强制关闭、崩溃或所有设备情形都能阻止。

请求取消不代表服务器回滚，关闭页面也不能证明请求未写入。草稿不自动持久化；若增加恢复能力，要单列存储范围、敏感数据、过期、账号隔离与清理，不暗中把所有表单写入 localStorage。

当前路由保护在 leave 与参数更新路径使用；不能据此声称所有 query/hash 导航和页面内部切换都已覆盖。推广时逐个明确“是否真的离开当前草稿”的边界。

## 11 权限 对象与异步结果保护

### 11.1 读取与写入分别判断

导航、页面入口、信息区和具体动作都按细粒度能力判断，不使用 admin／super_admin 等粗身份代替能力。可读不等于可写，可改模型不等于可删除，能管理某类对象不等于可管理所有目标。

写入前校验当前对象和能力，危险确认后再次核对，避免确认期间权限或对象已改变。前端控制用于引导、减少无效操作；最终授权必须在后端 service。不能因为前端隐藏按钮就宣告越权风险已解决。

### 11.2 本客户端保护

详情会话以稳定 ID／Hash＋类型定位，名称不能当主键。请求携带其对象、账号会话及本轮生命周期快照，迟到结果不得覆盖新对象、重开详情或另一账号。写入串行、重复动作去重；同页卡片与详情共用写锁和处理路径。

关闭／切对象期间的读结果、操作后刷新与主动读取都要核对当前性。权限失去时停止放行命令，明确反馈；不能继续利用旧详情数据执行写入。已实施的五页修复不等于全站读写协调架构已经完成。

### 11.3 异常必须表达真实结果

| 情形                               | 期望行为                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| 校验失败                           | 指向具体字段，保留用户输入，允许修正。                                           |
| 明确写入失败                       | 保留草稿或恢复已确认值，不展示虚假成功。                                         |
| 超时／断网、结果不明               | 说明未确认结果，允许先核对；不无条件自动重试非幂等命令。                         |
| 写入成功、随后读取失败             | 保留已知写结果，区分“已提交但未能更新显示”；不能简单描述为未保存并诱导重复写入。 |
| 服务端已更新但返回因后续读权限失败 | 属于已登记的接口契约缺口，前端无法据错误码可靠推断提交结果；需后端单独解决。     |
| 跨标签页／用户同时修改             | 当前无版本条件写契约，本地写锁不保证服务端并发安全。                             |

## 12 读取状态 更新与刷新入口

**以下为读取与更新的设计要求，不代表全部页面已接入。** 首次未取得结果、已确认空结果、已有可用内容更新、读取失败、无权限必须分开。快速刷新不应先清空已有列表／空态再闪回；不能用错误数据长度为零来渲染“还没有纹理”。

私有及管理页面应等待会话／权限恢复后加载，不能因刷新初期状态未知跳过首载。公共库不把任意 403 当作库关闭。加载表现按实际任务设计，不给全站机械添加同一种骨架，也不靠重建容器表达更新。

| 场景                   | 刷新／重载方向                                                                 |
| ---------------------- | ------------------------------------------------------------------------------ |
| 站点、邮件、彩蛋设置   | 保留“重新加载配置”，明确覆盖草稿；dirty 先确认，失败不丢草稿／基线。           |
| 通知中心               | 明确“更新通知”，保持筛选及仍有效的详情。                                       |
| 管理列表与应用审核     | 保留明确资源范围的更新，区块独立反馈。                                         |
| 个人应用开发者区       | 更新状态用于外部审核变化。                                                     |
| 个人应用已授权区       | 先补齐进入／返回／撤销成功／外部授权返回和失败重试，再移除常驻刷新。           |
| Fallback 状态          | 沿用自动更新及失败重试后裁剪重复手动入口；读取状态不等于立即触发后端健康探测。 |
| 公共库、个人角色、衣柜 | 维持无常驻刷新，确保进入、参数变化及操作后的更新。                             |

浏览器刷新保留整页初始化能力；不新增一个只调用 location.reload 的站内按钮。不先删刷新按钮再补更新路径。请求去重、响应顺序、过期时间、后台更新及缓存失效由统一读取设计协调，不在每个页面再散布一套定时器。

## 13 设置页的未保存状态

字段判断直接复用各组现有 useDirtySnapshot 基线，不能另建不同快照。改回确认值后 dirty 消失，保存成功只更新成功组基线，失败／部分成功保留对应输入及提示。站点设置及邮件 SMTP／验证配置使用字段级提示；其他设置按实际保存范围决定，不自动推广全站。

“未保存”不是字段验证错误，不能沿用红色错误框。字段复用 DirtyFormItem，在既有表单标签旁显示小号 warning 色“未保存”，不修改控件边框、底色或焦点；校验错误时隐藏该辅助提示，优先呈现错误。没有改动的字段不一起高亮。

同一保存范围已有字段级提示时，不再显示分组标题／主保存入口旁的重复标签：AdminSettings 三组与邮件 SMTP／验证组已移除。组级 dirty 仍是保存、重载、离开保护和失败保留的依据，不随可见标签删除。邮件的账户邮箱后缀策略保留组提示，彩蛋页保留现有页级／组级提示，其他页面不自动推广字段标记。

共享 DirtyTag 的可见文案统一为 **“未保存”**，不保留“有未保存更改／内容”等长标签。首页媒体、Fallback 配置及白名单编辑等原有调用只同步简写，继续使用原尺寸、语义色、位置与显示条件。离开／重新加载确认和正文说明仍用完整提示语，不机械替换完整句子。SMTP 密码／授权码不回显服务端原值；失败保留本轮输入，成功后清空并以清空后的表单建立同组基线。

首页媒体使用父配置级未保存状态；标签归属保存／放弃配置组，使用隐藏占位稳定布局，实际状态沿用 DirtyTag 的原生入场。混合提交语义保持。设置的保存提示与其运行效果分别验证；彩蛋还需核对主题覆盖对共享组件的影响，不能用保存成功推断效果已经正确触发。

重新加载、页面离开和浏览器离开各走相应保护；对象设置要求明确保存是刻意设计，不改成开关即写入。当前不宣称全站字段已迁移。

设置内容按任务、关联及依赖关系分组，不机械地将每个接口组做成一张卡片。展示组与保存／API 组分别约定；合并展示可沿用原接口，统一提交入口则必须同时定义写入范围、未保存归属和部分失败处理。不得仅为重排内容隐式改变后端权限、配置结构或事务承诺。

## 14 动效 首屏与滚动布局

### 14.1 已有动效约定

控件反馈、内容入场、展示场景分层，基础共享时长为 120／180／320／400ms；卡片错峰 30ms、总延迟上限 120ms；位移分别为内容 8px、卡片 12px、hover 2px。icon-swap 使用独立的 300ms 双向过冲与具名变量，不改变其他动效的标准曲线。

同组内容共享入场起点，首页标题、副标题和按钮整体一致；按钮文字与按钮容器不能分别挂不一致的入场。新卡片保持逐卡错峰，已有卡片数据更新不重播整页入场；刷新状态变化不通过重建容器制造闪烁。不使用全局宽度／定位过渡拖动导航。

减少动态效果遵循系统 `prefers-reduced-motion`，无站内偏好入口。减少时取消位移、错峰及非必要持续动画，内容仍立即可见，不能停在透明初始态。个人资料头像保留自身 hover 动画，只在支持 hover 且允许动态效果时运行。

### 14.2 首页与首次加载

主题和页面底色在 Vue 挂载前建立，首屏与仪表盘刷新不应先闪错主题底色。顶栏等待会话状态明确，头像固定占位；自定义头像可异步补入，但不先闪错误的字母默认头像。不能为了等待头像而阻塞整个导航。

首页标题、按钮和 footer 在 AppShell 视口内普通流式布局；唯一允许的页面级 fixed 层为纯背景画布。不得用手算视口坐标定位前景。背景 resize 不重建空画布，保持连续缩放修复；有图／无图、登录／未登录、桌面／移动均为高风险验证点。

首页玻璃按钮的颜色层与背景模糊分别存在，背景会改变颜色感知；评估时覆盖有图／无图和明暗背景，不仅凭一张截图判断着色是否生效。保留无边框设计，独立验证按钮对比度和焦点。

### 14.3 滚动槽与浮层

普通页面由根视口预留稳定滚动槽，首页由现有 AppShell 保留布局宽度，纯背景覆盖完整视口。浮层锁滚动期间，根视口不保留遮罩无法覆盖的空槽，将同一份 stable 预留移入 AppShell；不重复扣宽，不手算原生滚动条像素。

沿用组件库锁定／恢复和既有锁定类，覆盖 Dialog／Drawer、MessageBox、ImageViewer；嵌套子层关闭后父层仍保持锁定，最后一层关闭才恢复普通滚动。不能只让遮罩变宽而改变内容或导航宽度。

普通页采用 fixed 顶栏与同高流式占位；浮层期间 AppShell 的 overflow:hidden 会改变 sticky 的滚动参照，因此不采用依赖该祖先的 sticky。ResizeObserver 同时读取占位容器的实际宽度，顶栏沿用该宽度，不手算滚动条、不增加滚动监听或逐帧定位。根滚动区保留顶部 scroll-padding，降低锚点／聚焦被遮挡的风险。首页使用透明流式顶栏，认证页无顶栏／占位；滚动槽、浮层层级及恢复规则保持。

## 15 移动端与可访问性

窄桌面可操作不等于真实移动端可用。详情预览占比、短屏操作可达、表单软键盘、触摸目标、页头／工具栏、表格横向浏览、焦点返回及安全区域需分别验证；这些是设计要求，不表示所有移动场景已经完成适配。

预览不是移动端详情的唯一内容，首个主要动作不能被大块最小高度长期推到屏外。移动端若选择折叠预览、紧凑预览或不同布局，应在专项中确认；本初版不指定未经验收的新高度或 breakpoint。

可点击摘要、卡片及按钮需可键盘操作，重要含义不只靠颜色。标题有正确级别，输入有标签，纯图标有可访问名称，焦点清楚；浮层内部可以浏览全文和动作，关闭后回到合理入口。tooltip 不能吞掉按钮 Enter／Space。禁用与隐藏按实际状态选择，不用一排永久灰按钮代替清楚的信息结构。

## 16 设计交付与验证要求

每一批设计至少写清：对象／字段及其范围、信息顺序、动作可用条件、写入时机、dirty／busy、退出入口、成功／失败／结果不明、权限变化与迟到响应、桌面和窄／短视口。若涉及设置，再列分组保存／部分成功；涉及外部认证，再列跳转与返回状态。

工程验证按改动风险选择精确断言，fixture 与流程分离；涉及 API、存储、权限、关键交互和资源时覆盖具体请求、状态与失败副作用。构建／测试／样式断言只证明其覆盖的条件，不能代替视觉结果。仅文档批不为了形式重跑产品全测。

视觉、键盘及真实业务流程分别验证，不由构建或自动测试替代人工结论。发布前核对设计约定与最终实现、合理例外和未覆盖场景；设计规则维护在本文，具体进度及验收流水保留在本地开发记录。
