# 五类详情交互边界与权限方案

日期：2026-10-27。方案梳理的源码基线：`3349c63`，工作分支 `lylighte/feat-frontend`。范围为公共皮肤库、用户衣柜、用户角色、管理材质、管理角色的卡片与详情。

第 2 节保留该基线的扫描现状；本轮实现状态另见第 10 节。

这是[后续实施计划](前端整理后续实施计划.md)的专题核对。下文区分**源码现状**、**用户已确认**及**仍待讨论**。名称草稿阻止其他写操作、写入中禁止关闭和切换、第 4.1 节名称按需编辑与显式保存、第 5.1 节退出层级均已获用户接受。其他操作的确认强度及权限／影响范围专题仍单列待审，不把方案确认记为产品已实现。

## 1 目标与边界

目标是让每个操作明确回答：操作谁、何时提交、影响什么、何时确认、进行中允许做什么，以及失败后保留什么。

保持现有细粒度权限、后端作用范围和 API。只读信息与无权限、未加载与空结果、取消与失败、写入完成与后续刷新失败分别表达。暂不新增后端权限、归属接口、下载／邮箱／搜索能力、持久化草稿或通用请求框架；上传表单仍由原计划单独推广。

### 1.1 弹窗与浮层的实施范围

| 层级 | 本批范围 | 边界 |
| --- | --- | --- |
| 五个主详情 | 公共库材质详情、衣柜材质详情、个人角色详情、管理材质详情、管理角色详情 | 本专题规则针对这五个入口，不等于全站弹窗统一改为同一种保存方式。公共库本身没有名称编辑；其名称草稿规则不适用。 |
| 详情内字段编辑 | 个人／管理角色名称、衣柜备注、管理材质名称 | 只处理当前字段的未确认输入，不建立可回滚整个角色／材质的整表草稿；名称继续位于顶部。 |
| 命令／退出确认子层 | 这五处触发的清绑定、删除／下架、正版同步／解除，名称草稿的间接退出确认，以及待审的模型／公开／替换确认 | 操作确认只处理本次命令；退出确认只处理当前未提交草稿，不顺带保存名称或回滚其他修改。命令影响见 4.2，退出层级见 5.1。 |
| 只读子浮层 | Hash／UUID 全文、已有选择器与提示 | 不作为业务草稿，不进入业务写锁；Esc 先处理最上层，关闭子浮层不穿透主详情。 |
| 本批不推广的其他弹窗／页面 | 新建角色、纹理上传、建立正版绑定、远端导入、公告、账号／身份／OAuth 等表单与配置页 | 保留各自已确认的独立流程，后续按 3.6.8 等批次推广；复用 UiDialog 不代表本轮批量改其提交／关闭语义。 |
| 首页媒体局部编辑 | 不纳入本批保存触发调整 | 名称等修改归父页面配置草稿，局部完成不等于服务器保存；仍由父页面“保存配置”明确提交，不能套用详情名称的失焦策略。 |

### 1.2 本轮已经确认的保护

1. **名称草稿阻止其他业务写入。** 实际内容与已确认值不同才算草稿，聚焦或打开编辑本身不算。模型、公开、应用、头像、清除、同步／解除、删除／下架等写操作被阻止，当前名称的提交／恢复仍可用。预览、Hash 查看／复制和纯参数选择不因此禁用；模型／公开因选择即写，控件本身需要禁用。改回原值或本字段处理完成后解除限制。
2. **写入中禁止关闭和切换。** 主详情的右上角、遮罩、Esc 及程序关闭统一受保护；禁止切换对象及通过翻页、筛选、站内跳转离开当前写入对象。确认层在尚未发出请求前仍可取消。只读预览／复制不受业务写锁影响，浏览器强制离开只受可用的原生提示约束，不能承诺完全阻止。

3. **名称按需编辑与显式保存已确认。** 点击名称／编辑入口后才显示输入及保存／取消；失焦保留编辑，保存或 Enter 提交，取消仅退出当前字段。第 4.1 节具体行为保留，不把整个详情变成统一保存表单。
4. **退出层级已确认。** 名称取消／编辑区 Esc 只退出本字段；主详情 X 直接放弃未保存名称并关闭；遮罩／外层 Esc 有草稿时询问；子浮层退出不穿透，操作确认取消只取消本次命令，退出确认取消则继续编辑。写入中按同一写锁保护，已保存结果不回滚。

## 2 五处源码现状与缺口

| 位置 | 当前已具备 | 当前缺口 |
| --- | --- | --- |
| 公共皮肤库 | 添加检查 `wardrobe_entry.add.owned`，后端只允许添加当前公开库条目；重复添加已有衣柜记录不会新增计数 | 卡片添加未阻止冒泡，没有添加中的防重复；所有 403 均显示为“皮肤库已关闭”，未区分权限拒绝。 |
| 用户衣柜 | 元数据／公开／删除／应用分权；部分更新已捕获当前材质；应用有 loading；删除已有范围确认 | 备注以失焦／Enter 提交但缺少去重和写入互斥；详情迟到响应直接覆盖当前对象；详情失败仍留下列表快照并释放 loading，可能继续写；应用仅有 loading 展示，没有处理函数的重复提交保护；目标角色只取首 100 条，读取失败只写控制台；详情未接 dirty／busy 关闭保护。失焦提交本身不是本轮已认定的缺陷。 |
| 用户角色 | 改名、头像、清绑定、删除、正版同步／解除分别检查权限；危险命令已有确认 | 改名用 input change 提交，返回后直接修改当前 selectedProfile；清绑定成功直接关详情；删除同样不检查是否仍为原对象再关窗；缺少详情级写入互斥和 busy／dirty；正版读取错误与未绑定没有独立状态。 |
| 管理材质 | 名称／模型／公开／下架分权；取消公开及下架有确认 | 名称失焦提交；名称／模型返回后修改当时选中对象，可能串记录；没有完整 busy／dirty；下架把取消和真实请求错误合并吞掉；常驻影响说明待移除；身份现有邮箱兜底不等于已批准新增邮箱展示。 |
| 管理角色 | 清绑定捕获目标、两种清除互斥、确认后重验权限、更新列表和详情，并通过 busy 阻止关闭 | 改名仍可被失焦／Enter 重复触发，失败会抹去输入；改名后修改当前 selectedProfile；删除未复用清绑定的互斥／目标关闭保护，并吞掉真实错误。 |

UiDialog 已有关闭能力，但默认 `dirty=false`、`busy=false`。五处调用中，只有管理角色的清绑定实际传入 busy，不能仅因用了 UiDialog 就认为所有操作已经得到保护。UiButton 的 loading 也不能代替业务处理函数内的防重检查。

## 3 权限分三层核对

### 3.1 读取与操作分别判断

页面导航可以因持有其中一种能力而开放；这不授予该页所有资源读取能力。当前路由对 `/skin-library` 也先读取站点会话，公共 API 与未登录能否打开站内页面不是同一件事，本批不另改登录策略。

| 数据 | 当前后端读取条件 | 建议的前端边界 |
| --- | --- | --- |
| 公共库 | `texture.read.public`，且库配置启用 | 权限拒绝与库已关闭分别反馈；不将任意 403 当作配置关闭。 |
| 自己的衣柜及详情 | `texture.read.owned`，查询绑定 actor 的 user ID | 无读取能力不请求衣柜，也不把空数组称为“没有材质”；仅有创建能力时可保留独立上传入口，不凭写权限展示对象详情。 |
| 自己的角色 | `profile.read.owned`，查询当前用户 | 没有读取能力不伪造角色列表；部分创建能力不等于可读现有角色。 |
| 管理材质／角色 | 分别 `texture.read.any`、`profile.read.any` | 只有管理写权限不自动获得列表；不修改后端授权来补界面。 |
| 自己的正版绑定／外部身份 | 分别 `official_profile.read.owned`、`external_identity.read.owned` | 分开表达尚未读取、失败、无读取能力和已确认无记录；绑定读取失败不隐藏成“未绑定”，普通角色能力独立判断。 |

### 3.2 每个操作的权限与对象

表中操作还要求对应对象已被合法读取；这是详情界面的执行前提，不是新增服务端权限。`.owned` 和 `.any` 分开使用，不以 admin 身份兜底，不把绑定角色 token 的 `.bound_profile` 能力当作站点任意角色能力。

| 操作 | 当前关键权限 | 对象／后端范围 |
| --- | --- | --- |
| 公共库添加到衣柜 | `wardrobe_entry.add.owned` | 添加到当前用户衣柜；库条目仍须公开。 |
| 衣柜名称／模型 | `texture.update_metadata.owned` | 修改自己的衣柜记录；若是库原上传者还可能修改库名称／模型；皮肤模型同步该用户已使用此皮肤的角色。 |
| 衣柜公开 | `texture.update_visibility.owned` | 收藏标记为 `is_public=2` 的记录不能控制库公开；0／1 也不能证明原上传者身份，库联动受后端归属规则限制。 |
| 衣柜应用 | `texture.apply.owned`；界面目标选择还需 `profile.read.owned` | 后端同时验证材质在自己衣柜、目标角色归自己；不是允许对任意角色应用。 |
| 衣柜删除 | `texture.delete.owned` | 原上传者与收藏者存在两种删除范围，见第 7 节。 |
| 自己角色改名／删除 | `profile.update.owned`／`profile.delete.owned` | 后端验证角色归属。删除角色不删除衣柜材质。 |
| 自己角色清皮肤／披风 | `texture.clear.owned` | 只解除该角色对应绑定。 |
| 用作头像 | `account.update.self`，且角色有皮肤 | 修改当前账号头像；后端还验证皮肤在本人衣柜。角色仍绑定但衣柜记录已删除时，可能拒绝设置，不能仅凭 skin_hash 保证成功。 |
| 正版同步／解除 | `official_profile.refresh.owned`／`official_profile.delete.owned` | 后端按当前用户查绑定；不能操作他人的绑定。 |
| 管理材质名称／模型／公开／下架 | 分别 `texture.update_metadata.any`／同前／`texture.update_visibility.any`／`texture.delete.any` | 名称同步所有对应衣柜备注；模型同步对应衣柜及所有使用该皮肤的角色；公开同步库和非收藏记录；下架不等于撤销所有已应用材质。 |
| 管理角色改名／清绑定／删除 | `profile.update.any`／同前／`profile.delete.any` | 任意角色范围，但动作按独立能力呈现；不会顺带获得个人头像或正版管理命令。 |

### 3.3 建议呈现与拒绝处理

- 没有写权限：不呈现可执行写入口，有读取能力时继续显示信息。不能调用隐藏控件绕过检查，处理函数和确认返回后仍复核客户端已知权限。
- 有权限但对象条件不满足：保留适用入口并禁用，例如未绑定的清除、无皮肤的头像、未选择目标的应用；用已有提示说明原因，不补说明段落。披风没有模型选择；收藏记录不显示公开开关。
- 详情读取中／失败：不启用基于未确认信息的写操作。允许关闭、查看已获授权快照和重试；不将失败当作无记录、未绑定或收藏状态。
- 401 沿用现有 API client 的会话处理；403 明确拒绝，不无限重试。已确认读取权限撤销时停止展示相应受保护详情并清理未提交输入；不静默重新赋权，也不把仅失去某项写能力等同于全部读取失效。
- 应用目标区分“没有角色”“没有读取能力”“加载失败”，不能都呈现空下拉。后续通过现有游标接口完整读取或分页选择，不把首 100 条当作全量，不新增按 Hash 搜索。

## 4 各操作的建议提交与确认规则

下表名称编辑与第 1.2 节保护已确认，其余操作的确认强度与结束位置仍为待审建议。命令名称沿用已确认的信息／布局方案，不增加新的业务动作；不将其他字段一起改为显式保存。

| 操作 | 提交与确认 | 成功后 | 失败／取消后 |
| --- | --- | --- | --- |
| 名称／备注 | 已确认：点击名称／编辑入口后显示输入与保存／取消；保存或 Enter 校验提交，失焦不提交。同值不请求，角色名按现有规则校验 | 更新对应记录，回到名称浏览态，隐藏字段操作按钮，保留详情 | 失败保留输入与编辑态；取消仅丢弃当前字段草稿并退出编辑，不撤回其他已成功修改。 |
| 自己的模型 | 选择即提交，建议不二次确认；沿用影响本人关联角色的范围 | 采用服务端返回值更新模型和预览，保留详情 | 恢复最后确认状态；不在失败时显示选择已生效。 |
| 管理模型 | 选择后确认“会影响所有相应衣柜与使用该皮肤的角色”，再提交 | 更新已确认模型，保留详情 | 取消不提交，失败恢复已确认选择。 |
| 公开／取消公开 | 建议两个方向均确认：公开涉及可见范围，取消公开影响公共库展示；记录归属限制保持准确 | 更新已确认状态，保留详情；不把当前记录更新成功夸大为已核实库全局公开 | 取消恢复原开关，失败保留已确认状态。 |
| 应用到角色 | 先选目标，再点应用；目标对应槽位为空或已为同材质时不额外确认；替换不同绑定时建议确认目标及被替换的皮肤／披风 | 更新目标与相关预览，保留材质详情和目标选择 | 不写入错误目标，保留选择供重试；目标数据尚未取得时不猜测为空。 |
| 用作头像 | 点击即执行，建议不二次确认 | 保留角色详情；账号更新与头像图片生成分开反馈 | 原头像仍可用；写入成功而头像渲染失败时不说成账号写入失败，更不重复写入。 |
| 清除皮肤／披风 | 警告确认，明确只解除一个槽位、不删材质；已经为空时禁用 | 保留详情，卡片／字段／预览同时更新 | 取消不写，失败保留原绑定；清皮肤不误清披风，只有披风时不伪装成全部为空。 |
| 删除角色 | 危险确认，准确说明角色与正版绑定的删除关系 | 仅关闭被删对象详情，并更新列表 | 取消保留，失败显示真实错误。 |
| 删除纹理／强制下架 | 保留现有影响范围确认，见第 7 节 | 仅移除确认范围内的前端记录，关闭正确对象 | 取消与请求失败分别处理，不吞错误、不假设角色绑定已被清除。 |
| 正版同步 | 确认覆盖本地材质／模型及可能清空槽位；名称冲突采用实际结果 | 使用响应中的角色与绑定数据，保留详情 | 取消无操作；失败保留原状态，授权失效进入既有身份恢复流程。 |
| 解除正版绑定 | 确认只解除关联，保留本站角色、当前材质及外部身份 | 更新绑定状态，保留详情 | 取消／失败均不假装已解除。 |
| 公共库添加 | 点击提交，无二次确认；卡片与详情共用同一材质的防重状态 | 保留详情，不盲增收藏数；接口未返回新增／已存在区别时不捏造该区别 | 失败保留对象并可重试；条目已非公开时准确反馈。 |
| Hash／UUID 复制 | 悬浮／点击摘要看全文，点击完整原值复制，无确认 | 用现有反馈显示已复制，不触发其他写入 | 保留全文供手动复制，不关闭详情。 |

### 4.1 名称的按需编辑与显式保存

用户已确认本节方案：平时显示名称与编辑入口；点击名称或前方编辑按钮进入编辑，**保存／取消两按钮仅在编辑态出现**。名称字段流程按下表执行，主详情及子浮层的退出层级另在第 5.1 节对照既有规则说明。

[历史文档](阶段3组件与交互梳理.md)第 15.1、15.4 节曾约定 Enter／失焦完成字段即提交。当前主案是有意将名称改为明确完成的局部编辑；对象详情仍按项生效，其他模型、公开和独立命令不因此变成整表草稿。它也不同于站点设置的成组保存。

| 状态／操作 | 已确认的名称编辑行为 |
| --- | --- |
| 浏览态 | 显示名称和现有编辑入口，保存／取消隐藏；有改名权限时名称本身及编辑入口可进入编辑，无权限时仅为普通标题。 |
| 进入编辑 | 建立当前字段草稿，显示输入框与保存／取消，聚焦输入。进入本身不算修改，也不因此阻止其他写操作。 |
| 修改名称 | 草稿与已确认值不同后，按已确定规则阻止其他业务写操作；预览、Hash 查看／复制及纯参数选择可用。改回原值解除草稿限制。 |
| 失焦 | 不保存、不丢弃、不隐藏编辑按钮；用户可继续操作预览或查看信息再回来。复制与浮层获得焦点也不触发名称写入。 |
| 保存 | 使用“保存”按钮，Enter 为等价快捷方式；角色名沿用既有校验，衣柜备注空值按接口处理。无实际变化时保存禁用且 Enter 不请求，取消仍可退出。 |
| 保存中 | 保存使用现有 loading；输入、取消及其他业务写操作不可用；按已确认规则禁止关闭和切换，不能取消一个已经发出的服务器写入。 |
| 保存成功 | 使用已确认结果更新原对象和卡片，回到名称浏览态，隐藏保存／取消；保留详情，不等待整个对象另行保存。 |
| 保存失败 | 保留草稿、错误和两按钮，解除当前保存锁供修正／重试／取消；草稿仍阻止其他写操作，不静默恢复旧字把输入抹掉。 |
| 取消字段编辑 | 仅丢弃该次名称草稿，恢复已确认名称并回到浏览态，不关闭主详情，也不回滚其他已生效操作。这样“取消”对应的是一个明确进入的编辑过程，而非浏览态常驻命令。 |
| 字段内 Esc | 与取消本字段一致，恢复名称并退出编辑，不继续冒泡关闭主详情；中文输入法及更上层子浮层优先处理自己的 Esc。 |
| 关闭主详情 | 不由名称失焦触发保存；按第 5.1 节统一退出映射处理，不把字段取消与关闭详情混用，写入中全部受写锁保护。 |

保存、取消都位于顶部名称编辑区，复用既有 UiButton／输入组件及现成尺寸，不在下方交互区增加名称动作，不新增装饰样式。窄屏可按现有布局能力换行并避开主详情关闭按钮。按钮只在编辑态挂载／显示，无须在浏览态占一整行空位置。

这项名称编辑方案只用于个人角色、管理角色、衣柜备注、管理材质名称四处；公共库名称保持只读。它们共享编辑结构，但字段含义、权限、校验及 API 仍各自保留。管理名称的作用范围不因此缩小；是否另加范围确认仍待审，不自动给每次保存再套确认弹窗。

### 4.2 命令确认弹窗说明的范围

所有确认都必须写明本次对象及动作，不把“确认弹窗”本身做成编辑整个对象的表单；取消／Esc／右上角只取消本次命令，确认遮罩不执行命令或关闭主详情。确认后写请求已发出，关闭确认层不代表解除主详情的写入保护。

| 确认场景 | 需说明的实际范围 | 当前状态 |
| --- | --- | --- |
| 清除皮肤／披风 | 一个角色的对应绑定槽位；另一槽位、衣柜和库材质不删除 | 保留已有确认，呈现细节待审。 |
| 删除角色 | 角色记录及其可能存在的正版绑定；保留衣柜材质，不删除远端账号／外部身份 | 保留已有确认。 |
| 个人删除纹理 | 按原上传者身份存在仅自己衣柜或库条目及所有相应衣柜记录两种范围；页面不能确认归属；保留角色绑定、头像、文件 | 保留既有两种后果确认，不伪造仅移除入口。 |
| 管理强制下架 | 库条目及所有对应衣柜记录；保留角色绑定、头像与文件，不等于停用已应用材质 | 保留已有确认。 |
| 正版同步／解除 | 同步覆盖本站材质／模型并可能清空；解除仅删本站关联，保留角色及当前材质 | 保留已有确认，覆盖描述按实际 API 修正。 |
| 管理模型／名称 | 对应所有衣柜记录及模型关联角色的实际影响，分别按字段说明，不称为只改预览 | 模型确认、名称是否确认仍为建议。 |
| 公开／取消公开 | 可见范围及库展示，不能承诺当前接口未知的全局归属结果 | 双向确认仍为建议。 |
| 应用覆盖已有绑定 | 指定目标角色及对应皮肤／披风槽位，不影响另一槽位，也不删除材质 | 仅覆盖不同绑定时确认仍为建议。 |

名称放弃提示只覆盖当前未提交名称；关闭不会因失焦额外保存字段，也不回滚已成功的模型／公开等操作。不保留旧的“关闭先触发失焦写入”路径。操作确认与退出确认按第 5.1 节分别处理。

## 5 退出层级与写入保护

### 5.1 对照此前退出语义

沿用既有规则：**显式取消／X 表达放弃它所属范围，遮罩／外层 Esc 属于间接退出，有草稿时确认；已成功的服务器修改不回滚。** 名称编辑现在有明确进入和退出，因此“字段取消”与“关闭整个详情”分别落在不同层级。

2026-10-27，用户明确“接受方案”，本节退出对照记为已确认。该结论不扩大到新增模型／公开等操作确认强度，也不代表代码实施或视觉验收完成。

| 入口 | 无未提交名称时 | 有未提交名称时 | 影响范围 |
| --- | --- | --- | --- |
| 名称旁“取消” | 退出无改动编辑，不请求 | 直接丢弃本字段草稿，恢复已确认名称，退出编辑，不再询问 | 只结束名称编辑，主详情保持打开。 |
| 名称编辑区内 Esc | 退出编辑 | 等同字段取消，直接丢弃本字段草稿 | 仅本字段，不继续冒泡关闭主详情。输入法或上层浮层优先处理自己的 Esc。 |
| 主详情右上角 X | 关闭详情 | 作为显式退出，直接放弃本字段草稿并关闭，不自动保存、不再询问 | 当前详情及未执行的局部参数；其他已成功修改保留。 |
| 主详情遮罩／外层 Esc | 关闭详情 | 显示“放弃修改／继续编辑”；继续编辑保留草稿、错误和编辑态，确认放弃才关闭 | 当前详情。外层 Esc 指未被字段／子层消费的 Esc。 |
| Hash 全文、下拉等只读子层的退出 | 先关闭对应子层 | 同左，名称草稿保持不动 | 仅最上层子浮层，不穿透详情，不进入业务写锁。 |
| 危险操作确认中的取消／X／Esc | 取消本次命令，返回详情 | 名称有草稿时其他写命令已被阻止，不应另开该确认 | 只取消尚未发出的命令；确认遮罩不关闭或执行。 |
| 放弃草稿确认中的“继续编辑”／X／Esc | 不应无故出现该确认 | 返回原详情编辑态，草稿不变；确认遮罩不关闭 | 只取消本次退出意图，不能误当作放弃字段。 |
| 翻页／筛选切换对象、站内跳转 | 没有写入和上层子流程时正常执行 | 询问是否放弃当前字段，确认后才切换／离开，不保存名称 | 当前详情／页面流程，不清理无关表单。 |

主详情不额外添加暗示“取消整个对象修改”的底部按钮。保存成功已经回到浏览态，之后退出不再提示名称未保存；保存失败仍有草稿时按上表处理。例：先保存名称 B、再编辑成 C，此时取消字段或明确退出只丢弃 C，不把已保存的 B 恢复成更早名称 A。

Esc 每次只处理一个最内层目标：输入法组合 → 活动的子浮层／确认 → 当前名称编辑区 → 主详情。位于字段外且没有子层消费的 Esc 才交给主详情，不能一个按键连续取消字段并关闭详情。

### 5.2 请求与异常状态

| 当前状态 | 允许的操作 | 保护边界 |
| --- | --- | --- |
| 只读请求中 | 浏览合法快照、预览／复制已有信息、关闭详情 | 旧读取结果失效，不重开详情或覆盖新对象；未就绪写入口禁用。 |
| 写请求中 | 浏览、操作预览、复制已显示信息 | **已确认禁止关闭和切换**；名称取消、主详情 X／遮罩／外层 Esc、程序关闭、对象切换与站内离开均受同一写锁保护，重复／冲突写入被阻止。关闭只读子浮层仍可用。 |
| 写失败且已知未成功 | 修正、重试、取消字段或按 5.1 退出 | 保留草稿和错误，解除当前写锁；草稿继续阻止其他写入。 |
| 超时／断网导致结果不明 | 查看现有信息、重新读取核实，必要时明确退出 | 不自动重发写请求或宣称回滚，不永久锁窗；未核实前避免继续叠加同对象写入。 |
| 写已成功，后续刷新失败 | 保留成功结果，重试对应读取 | 不改报写失败，不再次写入；退出依是否仍有其他草稿判断。 |

写入已经开始后，任何“取消”都不能撤回已发出的服务端操作。命令确认在请求前可以取消；确认完成、请求已发出后，即使确认层已消失，主详情仍受写锁保护。

浏览器刷新、关闭标签页、地址栏跳转最多使用已有 beforeunload 原生提示，用户强制离开后不能保证拦截。前端取消等待不等于服务器撤回；新页面读取真实结果。草稿仅在当前页面内，不持久化敏感输入。

保护以对象为边界：角色用 ID，材质用 Hash＋类型，并记录本次打开详情的生命周期。所有请求返回先核对目标／生命周期，不能写回新 selected 对象或误关后来打开的详情。头像还需防止同一账号的头像写入重叠，不能仅按角色 ID 防重。

## 6 已有权限不等于越权漏洞已排除

核对的 service 路径确有后端权限与归属检查：个人角色不能操作他人角色，应用同时校验衣柜和目标归属，管理接口要求对应 `.any`，正版命令按当前用户查绑定。前端控件隐藏不是最终授权。

这只是本次指定路径的源码核对，不是全站安全审计，也没有运行真实越权请求。新布局必须保留这些校验；本次没有证据将已列 UI 竞态直接判定为服务端越权。竞态仍可能让界面显示错误对象或执行重复命令，必须按第 5 节处理。

## 7 后端契约限制与单列问题

### 7.1 删除与归属继续由 Issue 22 跟踪

当前个人删除依库原上传者分流，可能只移除自己衣柜，也可能删除库条目及所有对应衣柜记录。页面没有可靠归属字段，不能根据 `is_public` 或显示的上传者名称拆成两个实际上同接口的命令。

管理强制下架删除库条目和衣柜记录，但角色绑定、头像及文件保留；下架不是停用所有应用。个人公开也可能只改自己记录而未改库条目。继续使用现有确认并准确限定结果，不在前端补造归属／全局可见状态；[Issue 22](https://github.com/water2004/element-skin/issues/22) 的后端改造独立处理。

### 7.2 本轮发现的写后读权限组合问题

`LibraryService.UpdateTexture` 先调用 `UpdateForUser`，其事务已经提交；随后调用 `TextureDetail` 生成响应，而后者另要求 `texture.read.owned`。因此持有相应写权限、缺少读取权限且记录存在的主体，存在**写入完成但最终返回权限错误**的路径。

这是权限组合与返回契约的一致性问题，不等于该主体获得了未授权写能力。本分支不修改后端，也不声称前端禁用已修好接口。前端只能在无合法读取状态时不提供该详情写入路径；后端需要另行明确写接口是否预先要求读权限或采用不依赖再读取的返回方式，并补精确数据库状态测试。尚未创建新 Issue，不并入 Issue 22 的归属结论。

### 7.3 跨用户并发修改的边界

当前相关接口没有前端可用的版本号／预期旧值条件写契约。本批固定目标、互斥与生命周期保护解决当前客户端的重复写入和串记录，不保证阻止另一用户／标签页在确认期间修改同一对象，也不能把丢弃过期响应称为撤回服务器变更。需要检测或拒绝跨用户覆盖时另行设计后端并发契约，不在当前前端分支补造原子性。

## 9 已确认与仍需审查

以下是产品交互选择，不把工程防串记录等必需项混作额外功能：

1. **已确认名称保护**：名称草稿阻止其他业务写操作，查看／复制保持可用；草稿结束或改回原值才解除限制。
2. **确认强度**：自己的模型直接提交；管理模型与公开两个方向均确认；应用仅替换不同绑定时确认；管理名称是否额外确认仍待审。
3. **已确认写入保护**：写请求期间禁止关闭、切换及冲突写入；只读预览和复制可用。只读加载允许关闭的方案保留，未扩大为全站锁。
4. **结束位置**：修改、应用、清绑定、头像、同步／解除均保留详情；删除／下架才关闭正确对象。
5. **已有 API 限制**：本批继续保留准确的个人删除范围确认，不用新布局掩盖归属问题；写后读权限问题另行处理后端契约。
6. **名称方案已确认**：点击名称／编辑入口进入编辑才显示保存／取消，失焦保持编辑；显式保存或 Enter 才写入，取消仅退出本字段。字段流程见第 4.1 节，退出层级对照既有规则列于第 5.1 节，不恢复失焦保存的并行路径。
7. **范围已说明**：只涉及五处详情、其名称字段、命令确认及只读子浮层；不将规则直接推广到上传／新建等表单或首页媒体父草稿。具体新增确认范围仍按第 4.2 节待审项处理。
8. **退出方案已接受**：第 5.1 节的字段取消、主详情 X／遮罩／Esc、子层退出及两类确认取消，按用户本轮结论作为确定行为。

已接受部分按确定行为执行，其余待审项继续分别记录，不因本次退出方案通过而整体标记完成。合并批于 2026-10-27 获用户视觉验收通过，保留正版 UI 本地无法验证的例外，最终结论见第 10.3 节；本字段保存／取消复用既有组件，不增加后端能力。

### 10.1 本轮卡片快捷操作修订

个人角色卡片新增“设为头像”“清除皮肤”“清除披风”三个快捷入口，删除角色仍仅在详情弹窗。权限及皮肤／披风绑定缺失时不渲染对应动作，名称草稿或写入中禁用；卡片无可用动作时不留空操作栏。

用户进一步确认三个按钮均需 icon-swap：头像切换为设置图标，皮肤／披风切换为 X 图标。此能力尚未实现，映射、共享组件及动效约束统一见[后续实施计划第 4.1 节](前端整理后续实施计划.md#41-卡片)，纳入 3.6.5，不改变上述动作及权限边界。

卡片和详情共用页面处理函数与现有确认／权限复验，不打开详情来间接触发命令，也不增加后端能力。写锁覆盖卡片写入，不能在等待期间重复操作、切对象或打开新建／导入流程。头像所需材质归属等最终条件仍由后端判断，不把“有皮肤绑定”当作后端归属证明。

### 10.2 正版绑定分区与状态标签修订

个人角色详情按用户最新要求，将正版内容独立成区，排在普通角色信息之后、通用操作之前。区内顺序为“正版绑定”标题、远端角色名＋关联身份名称（为空则提供方名称）＋绿色正版标签、正版 UUID、同步正版数据／解除绑定。UUID 继续复用前八字符摘要、全文浮层与点击复制；不加新的展开／复制按钮或常驻交互说明。

同步与解除是该区专属动作，分别保留 `official_profile.refresh.owned`／`official_profile.delete.owned` 权限与原确认范围。名称草稿／写入中仍禁用；命令成功保留详情，解除后保留本站角色与材质。通用头像、清绑定及删除排在该区分隔线之后，不改变各自权限和影响范围。

个人角色卡片恢复绿色正版角标，与详情复用同一 `OfficialBindingTag`，按成功读取到的绑定判定；读取中、失败或失去读取能力不显示过期角标。读取异常在详情独立呈现，不能伪装为未绑定。模型、px 和正版标签统一 Element Plus 的 `default` 尺寸、胶囊及粗体；不增加全局覆盖，不给管理角色补造正版数据或新增 API。

工程结果与正版视觉验证限定见[后续实施计划第 12.6 节](前端整理后续实施计划.md#126-正版分区与标签反馈调整2026-10-27)。本修订不改变第 7 节后端契约边界，也不将新增确认策略记为已批准。
