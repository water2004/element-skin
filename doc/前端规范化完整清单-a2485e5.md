## 1 背景 目标与非目标

最初 3.1 扫描已关注颜色、尺寸、圆角、阴影、状态和动效。3.2 建立共享变量，后续组件迁移也有相应实现，但没有提供覆盖全部产品文件的残留账本。当前用户页与管理页标题不同、页宽分散等反馈，说明“公共组件已统一”不能等同“全站已规范化”。本次补全基线文件覆盖、原值位置、已有变量来源和处理归属。

“硬编码”在这里指源码中的显式值，不等同缺陷。已有变量的定义值、Tailwind 标准档位、协议码、UUID 分段、材质像素标准、Three.js 几何和工程配置均可合理保留。相同数字也未必表示同一种语义，不能把所有 20、64、768 或 1000 合并到一个常量。

本次不调整产品外观、不迁移变量、不修改 API／数据库／权限模型、不升级依赖、不恢复冻结 Webhook，不启动 3.6.5 或后续代码。清单是审查入口，不是全部条目已经审定或缺陷清零的声明。

### 2.3 采集与解析边界

- TypeScript AST 记录数值（保留负号）、布尔、字符串、正则及完整模板表达式，附外围变量、属性或调用上下文。类型字面量也保留，不误称运行时配置。
- Vue 解析 script、script setup、模板 class／属性／动态表达式及全部 style；CSS 记录声明、变量和带参数的 at-rule。标准 utility class 作为一个完整 class 属性记录，不把一个布局拆成多个彼此失去上下文的数字。
- 静态 CSS 模板按 CSS 解析；带插值的 TS 模板保留完整文本及表达式中的值，不执行模板，也不承诺还原其最终 CSS。模板普通文字节点、注释、生成资源及第三方依赖内部值不逐词采集；普通文案通过文案审查另核，包含参数的属性和脚本文案已在账本中。
- 列号用于定位字面量／属性附近；静态 style 的声明位置按属性入口记录。多行模板可能同时有整模板与内部声明来源，不能相加当作独立缺陷。
- 变量按名字关联定义，**没有执行 CSS 层叠、作用域、媒体条件或 JavaScript 分支**。同名来源不等于该页面实际生效来源；变量存在也不证明属性类型、对比度和视觉符合要求。
- 33 条路由包含 `/admin`、`/dashboard` 容器，以及创建／编辑、通知详情复用的组件。不是 33 套不同 UI；路由表中的“文件内最大宽度候选”包括内层区域，不能直接当作整页页宽。

## 3 目前最需要处理的规范缺口

### 3.1 页头与文字层级并未全站统一

共享 `components/common/PageHeader.vue` 当前使用标题 24px、700 字重、1.4 行高，副标题 14px、1.6 行高；可选图标 56px，图标字号 26px。其底距 30px、区块 gap 20px、图文 flex 基宽 240px、断点 768px 仍是局部规则。

`components/AppLayout.vue` 的旧 `.page-header` 则使用标题 32px、副标题 16px、底距 40px、标题底距 8px及渐变字色，没有同样的显式粗体。`assets/base.css` 又全局重置字重为 normal。因此截图中差异有明确代码来源，不只是管理员多一个图标。当前 14 个 Vue 实现使用 PageHeader，7 个页面实现沿用旧页头；应用表单、认证页、首页和 OAuth 面板另有本级标题。

处理方向为 3.6.7：先确定页面标题／分组标题／正文标题的角色，再统一来源和调用方。图标可选，不强制用户页套管理页外观；通知或公告正文标题不能直接替换成页面标题样式。具体字号、字重、渐变去留尚待该批确认。

### 3.2 页宽尚无共享分类

AppShell 普通主区有 20px 外边距，AdminView／UserDashboard 只是全宽容器。管理页自行选择 900、1000、1040、1100、1200px；角色／材质画廊及多处用户页面使用可用全宽。资料表单 600px、认证表单 440px、仪表盘局部 720px 等不等于整页最大宽。

处理方向为 3.6.7：确定阅读／编辑表单、数据表格、画廊、混合仪表盘的容器规则，明确页外距、最大宽、对齐及工具栏换行。不要将所有页面设为相同宽度。移动端预览占比、触摸及软键盘另属尚待确认的 3.7 专项。

### 3.3 共享组件已有来源，但不代表所有局部数值都应删除

已有颜色、字号、尺寸、间距、圆角、阴影和动效变量；UiButton／UiCard／UiDialog／UiViewerLayout、PageHeader、ActionBar、CardActions 等已承担公共规则。仍需核对公共组件内部的尺寸、图标位置、边框／焦点线、层级和各业务调用的 arbitrary class。

例如 UiViewerLayout 的 560px 最小高度、窄屏 340px 预览及 900px 断点是共享尺寸，但尚未证明适合手机；CardActions 的 92px 按钮基宽是可换行通用区规则，个人角色卡片三个等宽按钮为已批准的局部例外。焦点线 2px、边框 1px 等可保留为组件内部稳定尺寸，是否提升为变量取决于跨组件语义，而不是是否出现数字。

### 3.5 明确登记的文案与配置漂移候选

- `components/layout/useAppLayoutState.ts` 版本回退为 `v1.3.0`，`vite.config.ts` appVersion 为 `v4.1.0`；需核对缺少编译注入时的行为。这里登记差异，不直接修改发布版本。
- `storage/storage.ts` 的副标题回退仍有中英混排 `皮肤 management 站`，与首页／公共设置相关回退需对照来源和适用范围，不自动覆盖用户实际配置。
- 新建角色当前提示和限制为 **1–16 个英文字母、数字或下划线**；注册用户名另为 3–20。用户提及的 Mojang 3–16 是命名策略问题，不应在纯前端整理中暗改后端契约，也不能将账号名与角色名混为一套验证。
- `vite.config.ts` 多个开发代理指向 `http://127.0.0.1:8000`，属于开发环境配置；应统一来源时核对代理覆盖，不误报成生产站点的默认地址或安全漏洞。

### 3.6 变量完整性与合理例外

采集到 **122 个不同本地变量名**，包括主题、运行时局部键、组件库覆盖及彩蛋变量，不是 122 个全站设计 token。727 个引用位置已列来源。`--delay-index`、`--motion-card-count` 来自模板运行时 style；雪帽位置／尺寸来自 setProperty，不能仅因根样式无定义就报错。

`--festival-preview-background` 在中秋／春节模板有引用，没有静态找到声明，但使用 `none` 回退；保留为彩蛋专项核对项，不能据此判定普通预览丢背景。带插值模板整段记录可能再记录其内部引用，引用数不能用作运行时调用次数。

材质标准、UUID 格式、OAuth／HTTP 值、Three.js 相机／几何参数、彩蛋粒子／调色盘、依赖版本、工具阈值均在处理组中保留各自例外。例外需要可解释的用途，不是永久豁免：有重复、错误或无效实现仍应在所属模块重构。

## 6 后续如何使用此账本

### 6.1 每条迁移决策需要的信息

以记录 ID、固定源码路径／行和处理组定位，说明用途、实际消费范围、已有来源、是否与其他位置同义，再选择：保留局部、引用现有变量／组件、合并到所属业务常量、删除冗余、等待接口／设计决策。新增共同配置前，必须证明现有来源不能承担；不能建设一个不分领域的巨大 constants 文件。

仅在多处表达同一设计角色、需要同步调整或跨主题一致时提升设计变量；一次性的预览几何、协议长度和工程阈值留在所属模块并明确单位。Tailwind 负责常规布局，不要求把 `gap-4` 等正常档位全部改成自造变量；反过来，使用 Tailwind arbitrary 值也不等于已经规范化。

后续每批在计划中记录处理组、受影响记录／文件、保留理由、迁移提交及验证。该固定快照不回写成“最新源码”；需要新的全量基线时建立新快照并对照增减。设计约定按当前已批准规则维护，历史清单继续可追溯。

### 6.2 实施先后

1. 3.6.5 处理按钮 loading 呈现、指定 icon-swap 与适度 hover 细节；不先删除刷新入口。
2. 3.6.6 完成 AdminSettings 分组／字段未保存提示样板，以同一保存基线比较，失败和部分成功分别保留。
3. 3.6.7 先处理长页顶栏与滚动主体，再确定页头／文字／页宽分类，随后按本路由表逐页处理表格、表单、设置及工具栏布局。
4. 3.6.8 推广弹窗、上传和身份／OAuth 流程语义，保护首页媒体的父草稿与即时命令边界。移动端专项 3.7 的范围与排期仍需另行确认。

## 7 核验方法与当前结论
