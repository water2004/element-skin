# Issue #18 验证记录

## 环境与范围

- 基于上游 `dev@8177524`。
- Windows，本地 Go 1.26.5、PostgreSQL 17.6、Redis 8.10.2。
- 数据库和缓存仅使用本地测试数据。工具、日志、覆盖率文件放在被忽略的 `.cache/`。
- 未修改前端、UUID 生成算法或配置项；未重构账号登录流程，角色名查找统一使用新的匹配规则。

## 验证内容

- 大小写不敏感的单名/批量查询，返回原始显示名称。
- 并发创建相同名称的大小写变体：一个成功，其余返回名称冲突。
- 同一角色仅改变显示大小写；冲突改名失败后数据不变。
- 启动迁移直接复用导入角色候选名函数，覆盖占用后缀、16 字符截断、固定顺序及重复启动。
- 跨所有者冲突迁移保持 UUID、归属、皮肤、披风和模型不变。
- 候选 `_1` 至 `_99` 耗尽时，先前改名、迁移记录和约束变更全部回滚；释放候选后重试成功。
- 新公钥入口与原入口响应/响应头一致，沿用公开权限包装。
- 直接 Services 重写和转换到旧 account 批量接口两条路径。
- Services/account 回退源区分、缺失项与重复项、空值和请求数量边界。
- Services 单名未找到返回 404，旧 account 路径保持 204。

## 测试结果

全量运行命令：

```text
go test -p 2 -count=1 ./... '-coverpkg=./...' '-covermode=atomic' '-coverprofile=D:/skin-fix/.cache/coverage.out'
go tool cover '-func=D:/skin-fix/.cache/coverage.out'
```

最终全量运行退出码为 0，65 个测试包全部通过；跨包插桩后 `go tool cover`
输出 `total: (statements) 90.1%`，达到 90% 门槛。
`go vet ./...`、改动 Go 文件的 `gofmt` 检查及 `git diff --check` 均通过。
本轮包含公钥接口带尾斜杠/不带尾斜杠路径、迁移、并发冲突及跨模块集成测试。

PR 目标分支为 `dev`。仓库现有工作流仅监听 `dev` 推送、标签及面向 `main`
的 PR，因此本 PR 不触发该工作流；以上结果来自本地完整验证。

## 查询计划与验收边界

在 PostgreSQL 临时表中生成一万条合成角色名并建立 `lower(name)` 唯一索引。
单名查询和两个名称的批量查询均使用该表达式索引；没有额外逐名称数据库往返。
未运行额外的生产规模压测，实际维护窗口仍取决于角色数量和冲突规模。

本地 HTTP 测试模拟客户端的归一化与代理转换路径；没有运行真实 Minecraft、
authlib-injector 或 SkinsRestorer 客户端联调，也没有对生产数据库执行迁移。
