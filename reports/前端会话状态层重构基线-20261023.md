# 前端会话状态层重构基线（阶段 0）

日期：2026-10-23
分支：feat/frontend-session-store（基于 origin/dev f7369b4）
目的：在把 provide/inject 会话状态迁移到 Pinia 之前，冻结必须保持不变的可观察行为。阶段 1 完成后逐条对照验收。

## 范围

本次只动会话状态（user / authReady / fetchMe），不动 isDark、footerHeight、站点设置缓存、路由与权限逻辑。

## 必须保持的行为

### 首页（/）

1. 未登录：显示「登录账号」「即刻注册」两个 fixed 玻璃按钮。
2. 已登录：显示单个「进入个人面板」fixed 玻璃按钮。
3. 会话请求完成前（authReady=false）：按钮不渲染，不出现「先显示登录按钮再闪烁切换」。
4. 站点名称与副标题来自 appStorage 缓存首渲染，getPublicSettings 返回后更新。
5. hero 背景 canvas 为 fixed 全屏，滚动页面时背景不滚动；玻璃按钮 backdrop blur 生效。

### 顶栏 / 导航（AppLayout）

6. 未登录：显示登录/注册入口；已登录：显示头像、账号名、角色标签（超级管理员/管理员/普通用户）、通知入口。
7. 导航项按权限与 enable_skin_library 设置过滤。
8. 登出：调用 siteLogout，清空本地会话，跳回首页，100ms 后整页刷新。
9. 登录成功后 LoginView 调用 fetchMe 刷新会话并跳转。

### 会话副作用

10. fetchMe 成功：若 avatar_hash 存在则初始化自定义头像；刷新未读通知；启动 60s 未读轮询。
11. fetchMe 失败或登出：user 置 null，清未读指示，停轮询；authReady 仍置 true。
12. isLogged 变化（含初始 immediate）驱动未读通知的启动/清理。

### 数据页 inject 消费

13. DashboardProfile、DashboardRoles、DashboardOAuthApps、DashboardOAuthAppForm、DashboardIdentities、AdminUserList、AdminIdentityProviders、AdminOAuthApps、SkinLibraryView 读取 user；DashboardWardrobe、DashboardRoles 调用 fetchMe 刷新。

## 验收方式

- `npm run build` 通过；`npm run test` 全量通过（受影响测试改为 Pinia 而非 provide）。
- 人工四象限检查：桌面/移动 × 登录/未登录 的首页与顶栏，对照上面 1–12 条。
