## 修复前公共启动链路

1. 浏览器请求 HTML。`index.html` 只有空的 `#app` 和 `type="module"` 入口，没有在应用加载前应用主题、指定页面背景或提供初始内容。此时还没有 Vue 页面，存在空文档的绘制窗口，颜色取决于浏览器初始画布。
2. 加载 `main.ts` 的依赖图与样式。路由入口静态导入首页、仪表盘、后台和 OAuth 等页面；首页依赖 Three.js。开发环境还需加载并转换这些模块。CSS 进入后 body 才有项目背景色，此时 JS 保存的主题尚未应用。生产打包可缩短加载窗口，但没有消除该启动顺序。
3. `app.use(router)` 发起第一次导航。Vue Router 的 `currentRoute` 初值为 `/`、`matched=[]`，初始导航是异步过程。仪表盘的权限守卫还需等待 `getMe()`；首页无需该权限请求，但导航仍不是在安装插件时同步完成。
4. `main.ts` 直接 `app.mount('#app')`，没有等待 `router.isReady()`。因此 AppLayout 可能先渲染，RouterView 暂时为空。`useAppLayoutState` 只凭 `route.path === '/'` 判断首页，初始 `/` 被当成真实首页，套用单屏高度、透明主区、白色顶栏文字及首页根背景规则；仪表盘此时也会经过该状态。`html` 的黑色背景不代表 body 一定为黑，body 仍有自己的主题背景，不能将整个闪屏都归因于该条黑色规则。
5. AppLayout 挂载后执行 `initTheme()`，从存储读取主题或回退系统偏好，再更新根元素 `.dark`。随后并行发起 session store 的 `fetchMe()` 与公开设置请求。body 背景色有 0.5 秒过渡，早先背景与最终背景不同就有颜色切换窗口。
6. 会话结果返回，`authReady=true`，顶栏整组入口出现；权限决定通知入口和导航内容。头像缓存／皮肤渲染、通知未读查询分别异步完成。导航通过 ResizeObserver 测量空间后显示。这些属于后续补全，不是空 HTML 阶段。
7. 初次路由确认后 RouterView 挂载目标页面，才进入以下两个分支。路由完成与会话／公开设置请求的先后受响应时间影响，并无统一的“所有加载完再展示”屏障。

## 首页分支

`HomeView` 挂载 → 创建 WebGL renderer 并做首次合成绘制 → 启动循环 → 两次 requestAnimationFrame 后启动标题入场。

与此同时，请求公开设置，完成或失败后才请求首页媒体列表；列表返回后再加载图片或全景六面纹理。媒体未就绪时，循环清屏到 `#1a1a1a`；就绪后才绘制真实媒体。首页按钮独立等待 `authReady`，在自身挂载时执行 0.4 秒入场。

所以首页存在“空文档底色 → body／临时壳底色 → 深色画布占位 → 实际媒体”的可能路径。正常文字和按钮入场发生在这些启动步骤之后，不能单凭动画运行正常排除更早的闪屏。

## 仪表盘分支

权限守卫 `getMe()` 返回 → 路由确认为 `/dashboard/home` → 退出临时首页布局 → 挂载 UserDashboard／DashboardHome → 页面自身执行 0.4 秒淡入上移。

DashboardHome 的 onMounted 数据顺序是：公开设置 → Fallback 状态 → 公告 → 启动刷新定时器 → `getMe()` 读取统计。卡片可在数据返回前出现，初始统计为 0，之后更新。

权限守卫、AppLayout 的 session store、DashboardHome 的统计读取各自调用 `getMe()`，当前没有共享去重；这些请求的重复和串行数据等待会延长不同加载阶段。但统计接口慢不会阻止卡片初次挂载，也不能独立解释最早的空文档闪屏。

## 已确认的问题与修复边界

| 问题                     | 代码证据与影响                                                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 应用加载前缺少主题与底色 | index.html 无启动主题／背景；应用 CSS 和挂载后的主题应用发生较晚，初始画布与最终页面没有一致性保证。                                                                           |
| 初始未确认路由被当成首页 | main.ts 立即 mount；useAppLayoutState 只判断 path。隔离测试确认，仪表盘守卫挂起时 `path='/'`、`matched=[]`、`isHome=true`，RouterView 为空；释放守卫后才变为仪表盘与标准布局。 |
| 主题判定有两套不一致规则 | useTheme 只增删 `.dark`，从不设置 `.light`；base.css 在系统深色时对 `html:not(.light)` 应用深色变量。保存浅色也无法排除这条系统深色规则，可能出现应用状态与实际颜色不一致。    |
| 首页有独立的媒体占位阶段 | 媒体未就绪时清为 `#1a1a1a`；HTML、CSS 和画布占位底色没有贯通。加载媒体不应成为整站主题初始化的前提。                                                                           |

修复应保持在阶段 2：在首个可绘制阶段确定背景与统一主题规则；初始路由待定期间使用中性的稳定壳，或在正确底色下等待路由就绪，避免误用首页布局；首页画布占位与该底色衔接。直接只增加 `await router.isReady()` 会延长等待鉴权时的空文档，不能单独解决问题。

不需要通过延后整站显示、加长淡入或屏蔽内容来掩盖。路由／session 请求收敛和仪表盘远程数据状态可独立评估，不能混同为本轮闪屏已修复。
