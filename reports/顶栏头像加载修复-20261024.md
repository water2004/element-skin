# 顶栏头像加载修复

日期：2026-10-24。范围：阶段 2 顶栏与账户弹层的头像加载。

## 问题与原因

用户报告：账号已设置皮肤头部头像，刷新后仍先显示圆形首字母，再切换为自定义头像。

原 AccountMenu 用图片 URL 是否非空判断有没有自定义头像。会话返回时已经知道 avatar_hash，但 IndexedDB 缓存读取、缓存未命中时的皮肤加载与头部渲染仍是异步过程，URL 暂时为空，因此错误显示了默认首字母。即使已有缓存，读取也不是同步完成。

## 最终行为

| 状态                             | 顶栏／弹层展示                                       |
| -------------------------------- | ---------------------------------------------------- |
| 用户没有设置头像                 | 正常圆形首字母                                       |
| 已设置头像，缓存读取或渲染未结束 | 保留原尺寸方形空位，不显示首字母，不阻塞其他顶栏入口 |
| 头像 URL 到达，图片尚在加载      | 保留同一头像节点与尺寸，由图片完成加载，不插入首字母 |
| 自定义头像就绪                   | 显示皮肤头部图                                       |
| 缓存／渲染或图片明确失败         | 显示默认首字母；新图片到达或重试后可恢复             |

新增共享头像加载标记，配置状态与图片就绪状态分开传给 AccountMenu；顶栏 24px 和弹层 48px 的既有尺寸保持不变。去掉初始化中的重复缓存读取，继续使用现有 getAvatarForHash 和渲染缓存。

初始化使用请求序号保护：头像被移除、切换账号或请求先后完成时，旧结果不能覆盖当前图片或提前结束新请求的加载状态。布局同时观察用户 ID 和 avatar_hash；清除头像和退出账号时清理共享状态，相同账号与 hash 的普通资料更新不重复加载。

## 工程验证

- 全量前端测试：48 个文件、462 条通过；新增 12 条头像加载相关回归。
- 覆盖缓存延迟、缓存失败、缓存未命中生成、纹理失败后的 renderer 清理、头像移除与请求乱序、保存失败不改变当前头像／不发出变更事件。
- 使用真实 ElAvatar 验证：两个尺寸在等待期无首字母、URL 到达时节点保持、图片失败回退、新 URL 重试；顶栏从会话未就绪进入已设置头像状态时不会插入默认首字母。
- 生产打包、相关文件格式与 diff 检查通过。完整构建仍仅有 OAuthWebhookEndpointEditor.vue 原有 4 项类型错误，Webhook stash 未动。
- 本次未操作浏览器做视觉代验，未改用户正在填写的人工验收清单。原首页入场时序的条件放行状态保持原样。

- [x] 展开账户弹层：48px 头像与顶栏采用同样的加载规则。
